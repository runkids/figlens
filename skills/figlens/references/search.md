# Search and local index

The decision table in the [main skill](../SKILL.md#search-and-local-index) says when an index is needed. This guide covers the rest.

An earlier session, restart or other host may have enabled an index. A read-only `index` `status` finds it by the selector it was prepared with: `{"action": "status", "file": "<absolute .fig>"}` for one design, `{"action": "status", "workspace": "<project dir>"}` or the known `workspaceId` for a project. `file` never finds a project's workspace, and nothing scans for one.

- Absent or `uninitialized`: search the file as in the first row; do not prepare.
- `initialized`: reuse it within what it covers. Take the `sourceId` whose `path` is the design asked about and a prepared `scope` from its `indexed` entries; when no source has that path, search the file instead of adding it. Then search with `workspaceId`, `node` set to that scope and, when the workspace has several sources, `sourceId`; search the whole workspace only when the user asks. A node outside the prepared scopes is a file search, not a reason to widen the index.
- `storage_unavailable` or `permission_denied`: follow the failure rules below; when the `.fig` is readable, answer with a file search and say the index was unavailable.

Do not prepare an index because a search or usages call was slow, repeated or partial; offer it instead, since it stores data the user did not ask for. Connecting, listing tools, `find`, stateless search and stateless usages never create a database.

Opt-in steps:

1. Scope: the node the user chose (`0:0` is the whole file). Ask only when you cannot tell.
2. Call `index` with `{"action": "prepare", "file": "<absolute .fig>", "scope": "<node>"}` (CLI `index prepare <file.fig> --scope <node>`). figlens picks the storage (the per-user state directory, or the `--storage` an earlier prepare remembered); there is no setup command or database path to choose. For a project of several designs, also pass `workspace` with the project directory; later calls select it by `workspace` or `workspaceId`, not `file`.
3. The reply's job is dispatched, not done. Poll `jobs` with `{"action": "status", "jobId": "<jobId>"}` until `succeeded`; tell the user while it is `queued` or `running`, report `failed`, `cancelled` or `interrupted` as such, and `jobs` `cancel` it when the user asks.
4. Call `search` with `{"workspaceId": "<workspaceId>", "node": "<scope>", "query": "<words>"}` (add `sourceId` in a project of several designs), not also `file` (CLI `search --id <workspaceId> --node <scope> -- <query>`). Without `node`, search covers `0:0`, which a frame or page index does not; never widen the scope to fix that. Open each result with `inspect` on `ref.nodeId` in the `.fig` whose source matches `ref.sourceId` (paths are in `status` `sources`); node IDs repeat across designs.

Later searches, restarts and other hosts reuse that workspace. A reply with `coverage.complete: false`, or sources `pending`, `not_prepared`, `stale` or `incompatible`, is partial: say so and run the `nextSteps` it lists rather than guessing.

Maintenance `index` actions (each takes the selector above: `file` for one design, `workspace` or `workspaceId` for a project; `remove` and `relocate` also take `sourceId`), and what authorizes each:

- `refresh` rebuilds stale sources within the enabled scope; it needs no new opt-in.
- `rebuild` builds again from the sources (all, or one `sourceId`/`scope`); run it when the user asks or a reply lists it.
- `clear_cache` drops unused indexes and keeps the published one; `partial: true` means some were kept, so run it again later.
- `add`, `remove`, `relocate` (a moved `.fig` keeps its IDs; refresh after it) and widening the scope change what the workspace covers: run them on the user's request. `add` with a directory as `file` registers up to 10 `.fig` files under it, never through a link leading out of it; pass its `nextCursor` as `cursor` to add the next 10; report its `skipped` and `truncated` as they are, and prepare each file's scope on its own. `add` with a `gs://bucket/object` (not under `--root`) downloads it pinned to its generation and registers that copy; refresh and watch read the copy and never contact GCS, so add the object again to fetch a newer upload, and treat `remote.generation` as what was downloaded, not proof the object is unchanged.
- `reset` deletes that workspace database, never designs or exports, and `prepare` with `replaceUnavailable: true` and a new `storage` starts an empty workspace elsewhere: run them only when the user explicitly asked. A search, a cleanup, a yolo run or a host's automatic approval never authorizes them.

When an `index` call fails, follow its message and `recovery`, never work around it. `workspace_busy`: retry once after the other figlens process finishes or, over MCP, a pending reply arrives; from `watch` subscribe or ack it means too many checkpoints, so follow its `recovery` instead of retrying. `source_stale`, `cursor_stale`, `cursor_expired`: refresh or search again as told; for `changes` or `watch`, call it again without the cursor. `event_gap`: see Following changes. `query_work_limit`: run the listed narrower searches; the index is fine. `storage_unavailable` or `permission_denied`: ask the user to reconnect, restore or grant access; never change permissions yourself. Run `recreate_elsewhere` (`--replace-unavailable` with a new `--storage`; over MCP the directory must be under a server `--storage-root`, else use the CLI) only after the user confirms it, since the new workspace knows only the file you give it. Never get past a failure with another `--storage` alone, `index reset` or deleting figlens files. If the `.fig` itself is still readable, answer with stateless search (`figlens search <file.fig> <query>`, or the MCP `search` tool with `file`) and say the persistent workspace was unavailable; do not report its sources or paths.

### Semantic and hybrid search

Experimental and optional; text search stays the default. `search` with `mode: "semantic"` (CLI `--mode semantic`) ranks layers by meaning, `"hybrid"` fuses text and semantic ranks. Use it only when the user asks for it or a text search missed a synonym or purpose query, and say it is experimental: on the project's frozen suite the model missed its synonym/purpose quality gate.

- It needs a model the user set up. `models` `{"action": "status"}` (CLI `figlens models status`) shows whether one is configured. `configure` (`profile: "bge-m3"`, `modelDir`) checks files the user already downloaded (BAAI/bge-m3, at the revision `models list` shows) and runs the `figlens-embed` beside figlens once; figlens never downloads. Run `configure` or `remove` (forgets the profile, keeps files) only on the user's request. Over MCP, `modelDir` and its files must lie inside the server's roots. `siglip-base` (image; google/siglip-base-patch16-224, revision from `models list`) is configured the same way for image search (below).
- `mode_unavailable` on `semantic`: no model is configured. Search with `mode: "text"` instead, and say why. `hybrid` without a model answers as text: read `query.usedModes` and `coverage.layers.semantic.reasons`.
- `coverage.layers.semantic.state` `partial` (a `semantic_layer_building` or budget reason) means the layer is still building or hit a limit: no `nextCursor`; repeat the call to resume, and do not read absence as "no match". `properties_not_indexed` is different: the index predates property inputs, so repeating or embedding again cannot finish it; run `index` `rebuild` of that scope, then `embed`. Semantic matches carry `basis: "semantic"` and no text spans; names, effective text, an instance's component property values and each layer's page and container names are embedded (`matches[].field` says which); a value figlens cannot resolve exactly is skipped and counted in `unknownProperties`.
- Workspace search (`workspaceId`, `file`, `workspace`) reads each source's stored model layer and never embeds design text. A source with `coverage.layers.semantic.sources[].state` `pending` has no layer yet: call `index` `embed` (CLI `figlens index embed <select>`) only when the user asks, since it uses CPU and memory, then poll `jobs`. The MCP server and the watch runner also queue it after a text build; the one-shot CLI does not. If `models status` says `runtime_missing`, `runtime_changed` (an upgrade replaced it) or `model_missing`, follow its `recovery` (configure again) after the user agrees. A partial page has no `nextCursor`: repeat after the layer finishes.
- Visual search reads layers that `index` `visual` (CLI `figlens index visual <select> --scope NODE`) builds for one published scope: it renders that scope's screens and components, and embeds them when a `siglip-base` profile is configured. Run it only when the user asks for image search, then poll `jobs`; a unit that cannot render is reported on its own (layer `partial`) and text search keeps serving. Running it again on the user's request resumes a `partial` layer, retrying units that failed; search names that step only when the render budget stopped it. After a text build republishes that scope, the MCP server and the watch runner render it again; other scopes are never rendered implicitly.
- A running semantic search or `configure` can be cancelled. Each MCP/viewer process can keep one warm text and one warm image child after use; both can remain resident. Text alone uses about 2.5 GiB of RAM and both models about 3.5 GiB, besides the core and index workers; measurements, not caps.
- Live `figlens preview` offers Semantic, Visual and Hybrid. Enable an index only on the user's explicit indexing request or their Enable index button, for the named file and scope. Visual takes a reference PNG or selected stored layer and optional pixel crop; Hybrid can add text. Query images stay transient, results disclose model/render coverage, and Escape stops the model call. See Visual preview and handoff.

### Image search

Experimental, workspace only. When the user gives a screenshot or points at a result and asks for screens that look like it, call `search` with `workspaceId` and `image` (a local PNG path inside the roots) or `imageRef` (`sourceId`, `snapshotId`, `nodeId` copied from a result), optionally `crop` `{x, y, width, height}`. Add `query` text only when the user also names words; that makes it `hybrid`. Never pass a URL or base64.

- A stateless `file` search, or a source without visual layers, answers with steps: `index` `prepare`, then `index` `visual`. Run them only when the user asks; a search never builds them.
- Read `query.usedModes` and `coverage.layers.visual`: `visual_hash` alone means no vision model was used (not configured, pending or failed), so say results are by pixel hash. Results are similarity hints, not component identity; the ranking policy is still being validated.
- `source_stale` on `imageRef`: search again and copy a fresh reference. A partial page has no `nextCursor`.

### Where it is used

`usages` answers by exact id, never by name: two components called "Button" are two answers, so get the id from `search`, `find` or the user first. It lists linked instances only: a detached copy cannot be linked back, because figlens decodes no detach history from the saved file.

- `{"file": "<absolute .fig>", "node": "<componentId>"}` (CLI `usages <file.fig> <id>`) lists the layers that use it, nested instances and swaps (`I…;…` ids) included; for a COMPONENT_SET it lists `members` and every member's instances (`via` names the member). Pass `resource` with `VariableID:…`, `StyleKey:…` or `image:<hash>` (CLI: the id in place of the node) for the layers bound to it, and `direction: "out"` (CLI `--out`) for what one layer points at.
- With an enabled index, read it instead of the file: the same `node` or `resource` with `{"workspaceId": "<workspaceId>", "scope": "<prepared scope>"}` in place of `file`, adding `sourceId` when the workspace has several sources (CLI `usages --id <workspaceId> --source <sourceId> <id> --scope <scope>`). Keep `scope` a prepared one on every call. `scope` limits the returned locations, not the target: a component, variable or style defined outside the prepared frame still lists its uses inside it, so keep that workspace call rather than reading the file at `0:0`. Only when the user asks about locations in a scope that is not prepared, call with `file` and that requested scope instead of preparing or widening. Open each `ref.nodeId` in the `.fig` whose source matches `ref.sourceId`. The file form takes `scope` the same way (default `0:0`).
- Check `state` on every result: `resolved`, `missing` (the target is not in the file), `unresolved`, `unsupported`, `external` (a library; ask its cross-file uses with `library` below) or `recorded`.
- Hidden layers are left out unless `includeHidden` (CLI `--include-hidden`), and `coverage.reasons` then holds `hidden_locations_excluded`: an empty result with that reason is not "unused", and `coverage.complete: false` or a `partial` kind is unknown, not unused. A `node_not_found` error for a resource (an `image:` hash, most often) means nothing indexed in that scope records it, so it is unknown, not unused. There are no totals: page by passing `nextCursor` as `cursor` (CLI `--cursor`) while `hasMore`. Pass `source.snapshotId` as `snapshotId` (CLI `--snapshot`) to stay on one revision; `source_stale` means reopen the ids in the new snapshot first. `pending` or `not_prepared` carries the `nextSteps` call; run it only within the user's opt-in.
- For a library component, style or variable used across a prepared workspace, pass `library: {kind, namespace, key}` with `workspaceId` and no `node` (CLI `usages --file <file.fig> --library <component|style|variable> --namespace <ns> --key <key>`); take `kind`, `namespace` and `key` from the `library` field of an `instance_of`, `uses_style` or `binds_variable` result of `usages` with `direction: out` on a layer that uses it (a null namespace is unknown and cannot be asked yet). Each file's cached copy names the library, so `definition` stays `unresolved` unless `definition: {sourceId, snapshotId, nodeId}`, an exact ref from an earlier reply, selects it (CLI `--definition-source`, `--definition-snapshot`, `--definition-node`; then `selected`, `keyEvidence: unverified`); a source not ready carries `coverage.sources` nextSteps, `namespace_unknown` means a copy without a namespace may also use it, and `hidden_excluded` means hidden layers were left out, so an empty reply is not "unused". With a selected definition each result's `definitionMatch` is `equal` (its cached copy has the definition's fingerprint; not proof the library published it), `definition_mismatch` (the copy differs) or `unknown` (not comparable, such as a field holding a file-local id).

### Following changes

Only when the user asks to follow a design's changes from now on. That request is the opt-in for the scope's index and its history: when `status` finds no index covering the design and scope, take the opt-in steps above for that scope first, then track it, with no second confirmation. Reading `changes` of a scope already tracked needs no opt-in. A question about what changed between two copies, or one read of existing history, never authorizes `track` or a new index.

- Start: `index` with `{"action": "track", "workspaceId": "<workspaceId>", "scope": "<prepared scope>"}`, adding `sourceId` in a project of several designs (CLI `index track --id <workspaceId> --scope <scope>`). It builds a baseline as `rebuild` does; poll its `jobs`. Retrying the same `requestId` replays that job (none if the scope was already tracked) and reports tracking as it is now, so it never tracks again after `untrack`; use a new id. `untrack` stops recording for everyone and keeps the history; run it only when the user asks for exactly that.
- Subscribe: once the baseline job succeeded, `watch` with `{"action": "subscribe", "workspaceId": "<workspaceId>", "consumer": "<name>", "sourceId": "<sourceId>"}`, adding `scope`, or `node` for one exact layer (CLI `watch subscribe`); a node subscription reads only revisions naming that layer or its top-level frame, or whose impact lists that layer or a layer inside that frame, not changes deeper inside it. It starts at the newest revision and keeps its own checkpoint; a repeat returns the same `subscriptionId` at its own checkpoint (`initialPosition: existing`). A node subscription on a component main reads each revision that changes that main or a layer inside it, whose detail lists the instances it reaches; it is not a subscription to every instance's own override edits. `target_missing` or `identity_uncertain` means that layer cannot be followed: never pick a same-name one. Add `owner` (a name for this task) only for a subscription the task should not keep. Stop following: `watch` `unsubscribe` with your `subscriptionId` (or `consumer` and `owner` for the task's temporary ones); it never untracks or deletes history. Follow a search instead: subscribe with `query` (and `type`) for one source's `scope` (default `0:0`); after a refresh, `watch` `evaluate` with the `subscriptionId` stores the new top-50 evaluation (a watch lease on that scope stores it unasked), and `changes` with it reads the evaluations (`evaluation` `pending` names that evaluate step, `current_for_index` means the file changed since its index: refresh, then evaluate, and `unavailable` after a failed evaluation names its reason; `changes` never computes one). `enteredTopK`, `leftTopK` (exact refs in the new and old snapshot) and `rankChanged` (new-snapshot refs with `from` and `to`, null when `rankComparable` is false) describe the window only, not results added to or removed from the whole set; `source_changed` means new file bytes, `index_rebuilt` the same bytes reindexed. To follow it across several designs, pass `sources` instead of `sourceId`: `visible` (the designs you can see now; later ones are never added) or comma-separated sourceIds, at most 10 (CLI `--sources`); with `library: {kind, namespace, key, definition}` instead of `query` it follows that library item's uses and their `definitionMatch` (CLI `--library` with `--namespace`, `--key` and `--definition-source`, `--definition-snapshot`, `--definition-node`). `delta.changedSourceIds` names the designs with new bytes, `corpus_changed` a design moved or lost its index, or results ranked across several designs changed, `definitionMatchChanged` the uses whose match moved, and `coverage.transitive: not_followed` that the library's own libraries are not checked, with `delta.notFollowedSourceIds` naming changed designs that hold no use, whose dependents may be stale. `disabled` means a design in the set was removed (`disabled.reason: source_removed`) or the stored set is damaged (`sources_unreadable`): `unsubscribe`, then subscribe again; never reuse its old cursor. `workspace_busy` from subscribe or ack means too many checkpoints: `list` yours, then `unsubscribe` or `forget` ones no longer read.
- Read: `changes` with `{"workspaceId": "<workspaceId>", "subscriptionId": "<subscriptionId>"}`, or without a subscription `"consumer": "<a stable name for this task>"` (CLI `changes --id <workspaceId> --subscription <id>`), pages revisions oldest first after that checkpoint; a node subscription reads only revisions that change that layer, or whose changes reach it or a layer inside it as top-level frame, or whose comparison or impact is not complete. Each is a `baseline` (nothing compared; its `reason` says why, such as `index_version_changed` when an upgrade changed what the index extracts) or `changes`, with a `summary` of counts per change kind and facet. Page revisions with `nextCursor` while `hasMore`. A `changes` revision's `impact` (null for a baseline or one recorded before impact) says whether it is `complete`, its `reasons`, and `listed`, the count per class of the layers its detail lists, not a total. Pass a `revisionId` as `revision` to page its changed nodes (`entry` change), then the layers its changes reach (`entry` impact: `class`, `sides`, `facets`, `via`; `effective_unchanged` judges that layer's own fields only, not its children's, which are changes of their own), then `inspect` them; a detail page has no `hasMore`, so repeat it with its `nextCursor` until that is null.
- Acknowledge: after handling every revision of a page, including all its detail pages (a query subscription's evaluations page has none), call `watch` with `{"action": "ack", "workspaceId": "<workspaceId>", "subscriptionId": "<subscriptionId>", "cursor": "<nextCursor>"}` (or `consumer` with the same `sourceId` and `scope` as that `changes` call), so the next read starts after it. Ack only that revision page's `nextCursor`, never a detail page's; an empty page's is null, so there is nothing to ack. Repeating an ack is safe; the reply's `checkpoint` is the one held (acking a recovery page can move it back so kept revisions replay).
- Nothing is recorded until a build publishes. A `tracking` entry with `refreshRequired: true` means the file changed since its last build: run `index` `refresh` (no new opt-in) and read again; `trackingTruncated: true` means `tracking` lists only some scopes. `tracking[].model` is the semantic layer's readiness: a model or profile change is coverage, never a design change. An empty page never proves the file unchanged, and `coverage.complete: false` or `detail` `truncated` or `expired` is partial, not "nothing else changed".
- Keep it current while you work: `watch` with `{"action": "start", "workspaceId": "<workspaceId>", "scope": "<tracked scope>"}`, adding `sourceId` in a project of several designs, holds a lease while this MCP server runs (OpenCode's CLI-path `figlens_watch`: while this session lasts), and a shared runner refreshes the scope on each save, so `changes` shows new revisions without an `index` call. `stop` with its `leaseId` ends it early; `status` lists leases and the runner and writes nothing. CLI `watch run --id <workspaceId> --scope <scope>` holds one until its stdin closes. Only `changes.monitor.state` `watching` means saves are picked up: `inactive` (no lease, or the host stopped this server between turns) or `partial` (some tracked scope of the view has no lease) means run `index` `refresh` before trusting an empty page, and `unauthorized`, `source_busy`, `source_missing`, `source_unreadable`, `refresh_failed` (an `index` `refresh` reports why) or `stale` say why it is not watching. A start that returns `state: ended` (its `requestId` names an ended lease) needs a new `requestId`.
- `event_gap` (from `changes` or `watch` `ack`) means retention deleted revisions before this consumer read them: follow its recovery, which reads from the oldest kept, and tell the user the scope may have changed in between.
- A host note that says `figlens checked the watch targets` (Pi, OpenCode's CLI path) is data from a read-only `changes` of the subscriptions and consumers this session subscribed to or acknowledged: an unread revision or evaluation means design context read before it may be stale, so read and ack it as above; a baseline is no design change; `refreshRequired`, `trackingTruncated`, a tracking state other than `active`, an evaluation other than `current` or an unchecked target is unknown, and an unchecked target's `recovery` (such as `event_gap`) says what to do. Only `watch` `subscribe` or `ack` registers a target, so after a `watch` `start` lease, subscribe or ack a consumer to get notes. OMP, and OpenCode through MCP, only remind you to read `changes`. No note acks or authorizes anything beyond the task.

## What changed between two copies

To see what changed between two saved copies of a file, use `figlens diff <old.fig> <new.fig> [--node <id>]` (MCP `diff` with `old` and `file`): layers match by node id and type only (`lineage: unverified`), `unknown` means a side stopped or left that layer unexpanded, not that it was removed, a text diff with a side stopped at a limit prints `stopped early`, never `no changes`, so narrow it with `--node`, and a node on one side only lists its children for drilling in with `--node`; page with `--cursor`.
