# Rendering

How figlens turns expanded nodes into SVG and raster images: text styles and glyphs, image fills, effects and shadows, export areas and image adjustments. Load this before changing `src/render.rs` or `src/export.rs`; decoding, expansion and emitted fields are the `fig-format` topic. Format rules here were checked against the plugin's renders; claim accuracy only after measuring with the `accuracy` topic.

## Verified rules for text styles and rendering (2026-10-22)

- PNG exports/references use oxipng preset 0 (single-threaded) up to 4,194,304 px; larger images keep normal encoding. RGBA is exact; retain original bytes unless smaller. Decode budget: RGBA bytes plus rows; errors propagate. Source images and mip PNGs stay unchanged.
- A text node's font fields come from its text style (`styleIdForText`, local or `assetRef`), since a node's own copies can be stale; a hidden instance sublayer keeps its overridden values instead. `textAutoResize` is always the node's own.
- REST line height: kiwi `PERCENT` → `INTRINSIC_%`, px = fontSize × `derivedTextData.fontMetaData[0].fontLineHeight` × value/100, no `lineHeightPercentFontSize`; `PIXELS`/`RAW` → `PIXELS`. Percents are `f32(f32(ratio) × 100)`, Figma's rounding. `fontVariantNumericFigure`/`Spacing` → `opentypeFlags` LNUM/ONUM/TNUM/PNUM.
- `styleOverrideTable` entries list the REST fields their kiwi entry sets (`fontName` → the four font fields, `fontSize` → size and the line-height fields, …); an entry with `styleIdForText` adds that style's fields and `inheritTextStyleId`. Only ids used in `characterStyleIDs` appear. `lineTypes` maps `PLAIN`/`ORDERED_LIST` to `NONE`/`ORDERED`.
- Image paints use `<pattern>` fills so effects see the painted shape's bounds. FILL uses explicit centered cover dimensions with `preserveAspectRatio="none"`; the pattern tile clips it. An image `slice` creates an extra usvg clip group that resvg truncates to the outer canvas inside a pattern, cutting offset sprites in small exports. Regress with generated PNG/JPEG/WebP sprite slices at 1x/3x, with and without raster downsampling.
- STRETCH image fills (2026-10-29, #109) draw the image once: the pattern tile spans every image coordinate the node's box samples through the paint transform, with the image at 0..1 and the rest empty, so a transform past the image's edges leaves empty bands where it used to repeat the opposite edge. A transform within the image keeps the one-image tile and byte-identical output. A tile over 4 × the larger of the image's and the node's device area (a transform shifted far away, or a crop of a very different shape) spans only what the node samples, about the node's area. A skewed transform whose sampled range is still that large keeps the one-image tile, which repeats, rather than allocating it. Unverified against a Figma export: the empty area follows a downstream report that Figma leaves it empty. Strokes outside the box can still sample the next tile. Regress with the generated half-red image overshooting both vertical edges, including a shifted copy in a clipping frame.
- Unverified: TILE image fills (2026-10-29) repeat the image from the node's origin, each tile the image's natural size (kiwi `originalImageWidth`/`Height`, else the decoded size) times the paint's `scale`, as a pattern with `preserveAspectRatio="none"` keeping the tile's period (strokes outside the box sample the next tile); a tile over 2,048² device pixels (16 MB) is cut to the node's box, bounded like FILL, since resvg allocates the whole tile; without a usable size the fill is drawn as FILL. The paint's rotation is ignored. Not yet checked against a Figma export: the only samples (MCP Apps for Claude, 1024 px noise at scale 1 on smaller rectangles) never repeat, so the `imageTile` diagnostic stays `approximate`. Regress with the generated two-color tile, including a shifted copy in a clipping frame.
- SVGs use `viewBox="0 0 w h"` and move the origin in a transform: under a fractional viewBox origin resvg draws filters wrong.
- SVG definition ids are scoped to the exported node: `217:23093` yields `n217_3a23093-g1`. Non-alphanumeric UTF-8 bytes (including underscores) are escaped as `_xx`, so instance paths remain distinct and ids are XML NCNames. Only definitions referenced by `url(#…)` carry ids; groups have neither `id` nor `data-node-id`. CLI exports, bundle SVG assets, MCP and Pi share this renderer. Repeated exports of the same node are deterministic; duplicate inline copies of that node, or matching node ids from different files, still need caller-side namespacing for their definitions.
- SVG post-processing (2026-10-29, #76): exported SVGs draw in page coordinates under the one root `<g transform="translate(…)">`. Clip, mask, pattern, gradient and effect-filter geometry is in user space (`userSpaceOnUse`, the clip-path default), so it inherits that translate, and a large `gradientTransform` translation is expected. Consumers that inline, optimize or convert SVGs must keep the root transform and unique ids: disable SVGO `cleanupIds` or use `prefixIds`, and namespace duplicates as above. Before changing coordinates or ids for a browser misdraw, reproduce it the consumer's way: compare the unoptimized export in Chrome and resvg, then run the consumer's optimizer and inline two different exports in one page. Evidence: 139 icons with a clipping frame around a gradient-filled ellipse, from two private files, drew alike in Chrome and resvg, standalone and inlined together. After SVGO 4.1.0's default `cleanupIds` renamed their ids to `a`, `b`, …, the second icon of an inlined pair resolved `url(#a)` to the first icon's clip elsewhere on the page and vanished: 138 of 138 pairs, versus 0 with figlens's ids. Node-local coordinates were rejected: every SVG would change, and colliding ids would still resolve to the wrong definitions, only less visibly.
- An effect's filter region is the node's content uncut by its ancestors' clips (`_r.fb`: its own paint plus its children's, before its own effects; a clipping node cuts its children to its box) plus each effect's reach (1.5 × radius = 3σ, spread, offset). Not the render bounds: an ancestor may have cut those (a blurred glow at a frame edge loses the light it pulls in), and they already hold the effect's reach. Filter time grows with this area; counting the reach twice made frames with large shadows several times slower.
- Shadows follow Figma's SVG export: start from the hard alpha (`SourceAlpha × 127`); drop shadow = offset, blur, cut out under the node unless `showShadowBehindNode`, then a color matrix; inner shadow = hard alpha − blurred offset hard alpha.
- For rasterized pure layer/foreground blur, feed `SourceGraphic` directly to GaussianBlur: the shadow-only hard-alpha matrix is unused and the single-input merge is redundant. Keep the existing filter region, sigma and effect order; retain the original graph for SVG assets so bundle entries stay byte-identical. Shadow and mixed-effect graphs are unchanged.
- Strokes draw each side at its own weight (`render::stroke_weights`), so per-side strokes draw from saved `strokeGeometry` even with `strokeWeight` 0. Without geometry they fill the band between the box grown and shrunk by each side's weight as aligned, with square corners. Against saved geometry (2026-10-29), 51 of 64 nodes across five Community files and a production file matched exactly and the rest differed by under 1/255 mean.
- Export area (`render::export_area`): render bounds, else the box. `export --bounds layout` (MCP `bounds: "layout"`) uses `absoluteBoundingBox` instead, for any node that has one (not a page), and clips the drawing to it, since whole-pixel rounding of the output size would otherwise show overflow in the last row and column; every export reports `layoutBox`, `renderBox` and, when they differ, a warning with the per-side reach and its known causes: visible effects, a visible non-inside stroke, or a visible child past an unclipped box. A SECTION gets 40 px of margin and is drawn over the fills of the sections it is nested in, margin included; a page (CANVAS) is the union of its children over its background color. `export` refuses a hidden node (`visible: false`) in every format with `unsupported_node`, since it draws nothing; raster export used to write a blank image of its box.
- `export --match-dir DIR` compares an SVG export with the project's own icons; the mechanism and its measured limits are in the `discovery` topic.
  - Why this design (measured 2026-10-29): among nodes at most 64 px, instances (whose `componentId` already names the main) outnumber vectors and vector-only containers outside components 2155 to 1047, 762 to 240 and 509 to 24 in three component-based kits, while two kits without components had 0 and 8 instances against 153 and 64 loose ones, with no main to match, so the export is compared with the project's own icons. Plain mask IoU failed: same-name icons at two sizes scored 0.65-0.8 while unrelated badges sharing a background scored 1. Against Feather's stroked icons (288 files), 311 same-name outlined nucleus icons put the right file first 272 times and in the list 281 times, with 5.4 wrong entries per query on average; neighbours such as plus/minus and lock/unlock score above 0.9, so `similar` is a candidate list, not a verdict.
- Rasterized output (`Svg::for_raster`: render assets, reference, `export`) averages large image downscales first: a PNG fill is halved (2x2 means) while it stays at least twice the pixels it covers, since resvg samples a big downscale without averaging and it aliases. SVG assets keep the full image, as the plugin's do, since they may be drawn at any size. Its halving count comes from the image header, so a cached halving is reused without decoding the image again.
- An image is embedded once per SVG for each halving count (#134): `<defs>` holds it as a unit-square `<image>`, and every pattern that paints it places it with `<use transform="matrix(w 0 0 h x y)">`. A unit square keeps those scales within `num`'s four decimals; a pixel-size image would need the reciprocal of its size, which `num` rounds badly enough to misplace large images. An image whose aspect the renderer cannot compute (no readable size) is still written inline. Evidence: on the first 60 screens of two private files, SVG output fell from 212 to 145 MB and from 279 to 241 MB with no repeated payload left. PNG output kept its pixels: at most 1/255 per channel, and 9/255 on two antialiased edges. Chrome drew the SVGs the same raw and after SVGO 4.1.0 with `prefixIds`, inlined three to a page. Peak memory did not change (1.46 GB and 0.48 GB), because decoding the `.fig` dominates it.
- Image adjustments (kiwi `paintFilter`, REST `filters`), fitted to plugin renders: exposure e scales linear light by 2^(5e); saturation (kiwi `vibrance`) is SVG `saturate` (Rec. 709 weights) in linear RGB, e.g. −0.58 fits to a mean error of 1.5/255. The filter sits on the painted path: inside a pattern resvg filters at the tile's own size. Contrast, temperature, tint, highlights and shadows are not drawn yet.
- Effects drawn: drop and inner shadows, layer blur and background blur. Other types, such as Figma's GLASS, are skipped and reported rather than drawn as a layer blur, which made a glass input bar vanish (mean error 8.6 → 4.9/255 on that bar; no other sample uses GLASS).
- Background blur (2026-10-28): what the export has drawn behind the node, Gaussian-blurred with sigma = radius / 2 over the node's fill outlines plus 3 sigma, cut to those outlines and drawn under the node's own fills. On a Figma desktop screenshot of a glass card over a photo, radius / 2 left a mean error of 1.3/255 against 4.0–7.5 unblurred; radius / 1.5, / 2.5 and / 3 fit worse. Held out (a different file, radius 50 over a map): 6.4 → 3.5 inside the blurred card. The blur replaces the backdrop inside the outline: content drawn earlier is masked out there, as a half-opaque backdrop would otherwise be painted twice. Each cut is another layer that redraws the outlines it cuts, so cuts share the budget's size (at most 4,096, each charged its outlines' path bytes); past it the blur is painted over, which differs only for a translucent backdrop. Past the content's edge (the outermost clipping frame, else the export area) the backdrop is mirrored, as Figma blurs as if the edge continued: on the held-out card, leaving it empty raised the error at the card's ends from 3.6/1.5 to 6.1/3.9, and mirroring at the export area instead of the frame did not help. Mirrored tiles repeat as far as the blur reads, up to two past each side, and the filter region stops one export size past each side: resvg clears a filter, or crops clipped layers inside it, beyond that, so a radius much larger than a small export fades at its center. Only content inside the export is seen: exporting the blurred node alone gives it nothing behind, ancestors' masks, clips, opacity and blend modes are ignored, and an earlier blur is seen unblurred. While an export has an active background blur, drawn content is defined once in `<defs>` and referenced, and backdrops reference blur-free copies. Copies, or backdrops that include earlier blurs, grow exponentially with blurred siblings even when the SVG text does not: renderers expand references (12 chips expanded to 21.7 MB, then 0.34 MB). Past 64 blurs or 32 MiB of expanded backdrop per export (each blur counts as at least 1/64, since its Gaussian pass and redrawn images are not markup), later blurs are skipped so a crafted file cannot exhaust the renderer; the busiest sample (22 blurs) used 3.8 MB. Only a node's first background blur is drawn, and none on or inside a mask (masks are referenced by `url()`, beyond blur-free copies). Diagnostics report a node's extra blurs and a mask's own as skipped, but not blurs on a mask's descendants, since each node is diagnosed alone. Zero-opacity subtrees draw no background blur either, so they cannot use up the budget, and a blurred shape without fills counts its outline in its render bounds. Exports without a background blur or an unknown effect type are byte-identical to before.

## Known rendering diagnostics

Original-image reads enforce the shared per-image and per-scope [parsing budgets](parsing.md). These bound ZIP-decompressed source bytes, not decoded pixels or generated raster dimensions. Over-budget reads fail before output writing; ordinary image bytes and rendering remain unchanged below the limits.

What the renderer reports as skipped or approximated, how `export`/bundle warnings carry it, and measuring a warned layer with `export --hide`: [render diagnostics](render-diagnostics.md), loaded with the `bundle` topic.
