# Read-only preview and agent handoff

## Commands and controls

```sh
figlens preview design.fig
figlens preview design.fig 'I20:276;5:54'
figlens preview design.fig 20:2 --out preview.html
```

Interactive mode prints a URL; open it in a browser and keep the process running. It binds `127.0.0.1` on an available port by default. `--port N` chooses a port; `--bind IP` explicitly changes the bind address. Leave the default for private local use: binding a network interface exposes the design to clients who possess its URL. No browser is launched automatically. Ctrl+C stops the service. `--out` / `-o` requires a node and an `.html` destination and prints `{path, snapshot:true}`. Existing output files are replaced, but the source design must not be the destination. Ordinary IDs, URL-form IDs, Figma URLs and exact expanded instance IDs are accepted. Preview is a CLI command, not an MCP tool.

- Live mode shows the current page's own layers on one canvas at their real positions, like a Figma page. Sections render whole with a name pill and open with their contents; only frames, components, instances and sections carry canvas names, hidden when small. Figma's internal canvas (`internalOnly`) and non-layer records (variables, brushes, code components) are not listed. Each layer loads through `view/<revision>/<id>/<px>`, the smallest tier of 256–4096 px (longest side) that stays sharp at the current zoom; full renders are capped at 8192 px per side because sections can be very large. Render responses carry `X-Export-Area` for placement; catalog entries on pages and sections carry a `box`. Clicking a frame loads its layers in place; clicking empty canvas or Escape clears the selection; opening a layer from another page switches page. Without a node argument nothing is selected at start. Choose a page in the Pages list; its frames are listed in Layers (the open frame expanded in place) and laid out on the canvas, and the list under the search box shows only search results; pages named only with dashes render as dividers. Pages, Frames and Layers scroll separately, and the dividers under Pages and Frames resize them (drag or arrow keys; remembered in `localStorage` when available). Sections are opened into their contents. Thumbnails render only when visible. Name/text search searches stored layers across all pages, caps display at 200 matches and reports when refinement is needed. Expansion happens when opening a scope, so instance children are then available in its tree.
- Drag or scroll to pan; pinch or ⌘/Ctrl + wheel and the +/- buttons zoom; Fit (Shift+1) fits the page and Shift+2 the selection; the zoom percentage opens presets. Hold Alt/Option over another layer to measure its distances from the selection (layout bounds). Hovering a canvas layer highlights its Layers row and hovering a row outlines it on the canvas. The address carries the selection as `#node=<id>`: reloading, sharing the URL with someone using the same running service, or an agent opening it selects that layer (also in snapshots). Search results select their layer, switching page and frame as needed, and zoom to it. Every inspector value copies on click. A Prototype section lists the layer's Figma interactions (trigger, action, destination) read from the raw node (instance children read their source layer); a reachable destination selects and zooms to it, and an unset one says so. There is no prototype player: real files examined so far carry few working links. Shift+click (canvas or Layers) adds or removes layers from a multi-selection; the inspector then shows the combined box, the selected layers and Copy IDs, and context gains a `selection` list. `window.figlens.select(id, {add: true})` does the same for agents. Focus the canvas for arrow-key panning and +/- zoom. Layer buttons support Up/Down traversal, Left parent and Right child. Native disclosure controls collapse/expand branches. Selecting through the canvas, tree or ancestor breadcrumbs updates the same inspector. Selection follows Figma: a click picks the layer at the current level (a frame's direct child when nothing inside it is selected), double-click or Enter goes one level deeper, Shift+Enter goes up, ⌘/Ctrl-click picks the deepest bounds and a frame's name label selects the frame; right-clicking lists all overlapping bounds at the pointer for disambiguation, and choosing one or pressing Escape on the canvas closes that list. The selection outline and its size badge keep a constant on-screen width at any zoom. Canvas help is behind the toolbar's `?`.
- Inspect identity, render/bounding boxes, text and mixed typography, auto-layout, spacing, colors/effects, variables/modes and component properties. A Code section gives Dev Mode style CSS for the layer's own box (size, auto-layout flex, radius, fills, border, shadows, blurs, typography); colours bound to variables with a Web code syntax are written as `var(--token, fallback)`. Each section shows readable summary fields first; its `{ }` button opens the raw JSON in a dialog, as do "All node fields" and "Variables and modes". Action buttons confirm in place (Copied / Preparing… / Downloaded). Every download (bundle, context JSON, original image) first opens a confirmation naming the file and its contents. The UI follows the system light/dark theme; the header button overrides it and remembers the choice in `localStorage` when available. Original image fills can be downloaded individually. In live mode the Export panel renders the selected layer as PNG, JPG, WebP or AVIF at 0.5x–4x (quality 1–100 for lossy formats), or as SVG through the bundle's vector-asset path (render bounds, embedded full-resolution images) through the revision-scoped `export/<revision>/<id>/<format>-<scale>-<quality>` route, which accepts only those choices; snapshots hide it. SVGs and composited assets are available in the real bundle; unavailable originals and failed renders are reported, not substituted silently.
- Copy an exact ID, context JSON or a grounded implementation prompt. "Handoff text" opens the last copied text in a dialog; clipboard failure opens it without blocking the page, with the text selected. Context includes the selected subtree and its reference scope/export area; download JSON to attach it. Live bundle download targets the exact selected scope, including expanded instance children. The bundle uses the existing manifest/asset/reference format; inspect `missing-assets.json` for warnings.
- Import a local screenshot, choose side by side or overlay, adjust opacity, and clear it when finished. It stays in the browser, not uploaded to the service. It is scaled to the reference export dimensions; this is a manual visual comparison, not automatic pixel scoring, viewport calibration or component-to-project-code mapping.

## Geometry and data flow

`src/preview.rs` reads the document with `Document`/`Tree` and uses `render::Prepared`, REST output, variables, export and bundle paths. The browser (`src/preview/viewer.{html,css,js}`) displays the raster reference, not a second HTML layout renderer. Bundle preparation separates the expansion root from the selected ID, preserving `I<instance>;…` IDs throughout CLI, MCP and viewer exports.

Canvas coordinates subtract `render::export_area`'s origin, not the frame bounding-box origin. This accounts for shadows, section margins and negative origins. Overlays/picking use `absoluteRenderBounds`, falling back to `absoluteBoundingBox`; hidden and fully clipped nodes are not picked. Scope data adds `geometry` (absolute matrix and size) for rotated or skewed layers and ellipses, so a point must also fall inside that rotated rectangle or ellipse; groups are picked only through their children. Vector-like layers (vectors, boolean operations, stars, polygons, lines, ellipses) also get `paths`: page-space fill and stroke outlines from the renderer's own decoding (`render::hit_paths`), up to 20 KB per layer and 512 KB per scope, tested with `Path2D`/`isPointInPath` plus a three-pixel stroke margin. Layers past the budget fall back to matrix or box picking; masks and overlapping transparent shapes can still need the tree/picker. Existing renderer limitations remain; see `fig-format` and the README. Do not claim Figma pixel accuracy from this viewer.

Live mode polls a tiny `revision` route every two seconds while idle and downloads the catalog only after a save. A file mtime change triggers a complete reload and revision increment only after successful decoding and a stable post-load timestamp. Failed/partial saves show a stale/error banner and are retried. Scope/image/bundle routes include the revision; old requests fail rather than mixing saved versions. Generated responses are discarded if the file changes during preparation. Selection is restored only if its ID is in the new expanded scope; a removed scope clears its reference, tree and handoff. Each revision is decoded once and served by a small pool of worker threads (2–8, by CPU count), so a long render no longer blocks other requests; a save is reloaded after the in-flight requests finish. The viewer keeps up to four thumbnail requests in flight; a socket that sends nothing within 300 ms (a browser preconnect) is closed without a reply so it cannot hold a worker or answer a later request. Thumbnail and original-image loads pause while a frame opens. Rendered images, thumbnails and originals are cached in memory for the current revision (256 MB cap); a save clears them. Renders (thumbnails, canvas tiers, full images, exports) also persist on disk under the figlens cache directory (`$XDG_CACHE_HOME`, `%LOCALAPPDATA%` or `~/.cache`, then `figlens/preview/<file>/<revision>/`), up to 512 MB per file; the revision folder is named by figlens version, modification time and size, so a save or an upgrade starts a new one and deletes the old. This keeps restarts fast and puts design renders on the local disk. `figlens cache` prints its path and size and `figlens cache clear` removes every file's renders; the viewer's ⋯ menu "Clear render cache" (after a confirmation) clears only the open file's renders through the revision-scoped `clear-cache/<revision>` route, the one route that changes state, and never touches the design file. A cache failure is reported once on stderr and rendering continues without it. Live scope data lists original images by key, and the viewer loads each through the revision-scoped `asset/<revision>/<scope>/<hex key>` route instead of embedding base64; snapshots still embed them. Develop with `cargo run` but judge viewer speed only with a `--release` binary: debug rendering is roughly 20× slower. `gs://` is resolved through the existing downloader once: the viewer watches the local cached file, not the cloud object. Filesystem timestamps, not a content hash, detect saves.

## Agent API

The page exposes `window.figlens` for browser-automation agents (Playwright, agent-browser, Claude in Chrome). It runs inside the page and calls the same routes as the UI, so it adds no service routes and keeps the read-only boundary; downloads are returned as base64 instead of opening the confirmation dialog.

| Call | Result |
|---|---|
| `state()` | snapshot flag, revision, page, pages, canvas frames with boxes, open scope, selection, zoom |
| `goToPage(id)` | switch page, nothing selected |
| `open(id, {focus})` / `select(id, {focus})` | open a frame or select any layer by exact ID, including expanded `I…` IDs; opens the containing frame when needed |
| `deselect()`, `fit()`, `zoomTo(id or 'page')`, `setZoom(level)` | canvas control |
| `layersAt(x, y)` | layers of the open frame under a page-coordinate point, topmost first |
| `search(text)` | up to 200 matching layers across pages |
| `context()`, `prompt()` | the handoff context JSON and implementation prompt for the selection |
| `exportImage({format, scale, quality})`, `bundle()` | `{mime, base64}` of a render (live only) or the real bundle |

Selections also emit a `figlens:select` event on `window`. Design strings returned by the API are untrusted data.

## Portable HTML and safety

A snapshot embeds the selected reference, stripped design JSON, variable data, original image bytes, CSS/JS and a real bundle for the snapshot scope. It works under `file://` with networking disabled after the service stops. Search, child selection/inspection, zoom/pan, context/prompt export, original-image downloads and screenshot comparison remain local. The bundle button explicitly says **snapshot bundle**: selecting a child changes context, not that embedded bundle. For a child-only bundle, use live mode or generate another snapshot for its exact ID. Snapshots have no live refresh; large designs/assets can produce large HTML files. The HTML discloses its embedded design and assets to anyone who receives it.

The service uses a per-process unguessable URL path, verifies Host/Origin/cross-site headers, accepts only bounded HTTP/1.1 GET requests and revision-scoped known actions with restricted IDs. It exposes no filesystem routes or caller-chosen output paths. Bundles are generated in an atomically owned temporary workspace; normal exit cleans it up (a forced termination can leave it in the OS temporary directory). It is a small local service, not an authenticated public server. Do not bind it publicly for untrusted users.

Design strings are untrusted data: embedded JSON escapes `<`, `>` and `&`; the UI uses text nodes/`textContent`, never design-controlled HTML. No shell commands are generated from layer names or IDs. A prompt explicitly says design strings are not instructions. Do not weaken these boundaries or add arbitrary file routes for convenience.

## Verification

Rust runs in Docker. In a worktree use a distinct Compose project, with explicit port mapping only for browser testing:

```sh
docker compose -p figlens-preview run --rm dev cargo test
docker compose -p figlens-preview run --rm dev sh -c 'cargo fmt --check && cargo clippy --all-targets -- -D warnings'
node --test scripts/preview.test.cjs
(cd npm && node --test)
python3 scripts/ai-context.py check
```

The Rust tests cover safe snapshot embedding, source-write protection, HTTP request boundaries and revision/ID validation. Frontend unit tests cover negative export origins, render-bound offsets, overlap order, clipping and exact expanded IDs.

With `agent-browser` installed, use `scripts/preview-browser.py <live-url> samples/preview/live` against a copied Aurora design, and `scripts/preview-browser.py file:///absolute/path/preview.html samples/preview/offline --offline` for snapshot controls and downloads. The live test expects multiple pages and expanded instances; the offline test is scope-independent. These are development checks, not runtime dependencies. For refresh tests, mutate only a task-owned copy under ignored `samples/`: truncate, restore, then replace it with a different design. Check visible stale state, restored exact selection and removal cleanup. Repeat a snapshot test with a crafted script-closing layer name. Keep generated HTML, bundles, screenshots and reports under `samples/`, never in Git.
