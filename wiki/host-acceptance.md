# Host acceptance

How the installed-host lanes check each host entry from one extracted npm candidate; the entries themselves are in [integrations](integrations.md).


`npm test` checks shared state, cancellation, native review logic, ownership, override preservation and exact maintained staging. `scripts/check-installation.py` installs an extracted candidate tarball in a fresh consumer, verifies cold/warm/parallel launcher behavior and native/wrapper MCP (`mcp_smoke.check_mcp` also runs `search`, opens its exact ref with `inspect`, runs a file `usages` and runs `diff` on two copies of the fixture, which must be two sources with no changes and complete: wiring evidence, not the revised-pair engine; Pi's registered MCP command uses the same check, which is Pi's `usages` acceptance). `mcp_smoke.check_first_use` then starts the native, wrapper and Pi MCP commands from clean roots each: no state from connect, list, find, stateless search or stateless `usages`; workspace `usages` after the build; `index track`, its `changes` baseline and a `watch ack` that leaves the next poll empty; a `watch` `start` another host's `status` shows as not `mine`, ended `released` once the holding host's input ends; concurrent prepare joins one database; cancel, restart reuse, `clear_cache`, `rebuild`, `reset` and re-prepare keep the source and other workspaces; a missing remembered root and (non-root POSIX) read-only storage fail with recovery. `check_reuse` then starts the wrapper on the native run's roots and searches that workspace without preparing (cross-host reuse). The report's `firstUse` lists what ran or was skipped. It then optionally runs host profiles. Existing CLI Node 18 and Pi 1.3.0/1.4.0 lanes remain.

- OpenCode: `--opencode-bin <binary> --opencode-sdk <@opencode/client-root>` runs `check-opencode-integration.mjs`, including real server/TUI, managed MCP, a scripted session lane (a test-only plugin registers a loopback OpenAI-compatible provider whose fixed Code Mode `execute` calls run `search`, then `inspect` on the returned `ref.nodeId`, then `diff` on two copies of the fixture; routing evidence, not a model; the session starts only after the managed tools reach the registry, recorded as `catalogAfterConnectedMs`, so an empty first search fails, #125), PNG bytes, permissions, mapping round-trip, two viewer owners, session deletion and reload. First-use lanes, also scripted: no `figlens` state after connecting, listing and stateless search; prepare, job polling, workspace search, inspect and workspace `usages` (same `sourceId` as the search) through managed MCP; a `figlens_index` deny rule keeping the database while an allow resets it; and, after a reload with a disabled user override, the same flow through the CLI-path tools, then `track`, a `changes` baseline, its `watch ack` and an empty `changes` after it. With that override, `figlens_watch` `start` under a denied `read` starts no lease, `status` works under a denied `edit`, one session's lease records a save the plugin's `figlens_changes` then shows and its own `stop` releases, a repeated `requestId` returns the same lease, another session's `stop` of it is refused, and session deletion or a reload releases a held lease. A consumer the session acknowledged is then checked before a later prompt: no note while it is current, a data note with `refreshRequired` after the fixture's stamp changes. Through managed MCP, a consumer acked inside a Code Mode `execute` gets the explicit-check reminder in the next prompt's system text.
- OMP: `--omp-sdk <@oh-my-pi/pi-coding-agent-root> --bun <binary>` runs `check-omp-integration.mjs`: real loader/approval wrapper, descriptor/bridge MCP (including `search`, `inspect` of its exact ref and `diff` of two copies, and first use: no state from connecting, prepare, job polling, workspace search, inspect, workspace `usages`, `track`, a `changes` baseline and its `watch ack` at the `write` tier, a `watch` `start` the bridge's disconnect ends `released`, and OMP's own approval decisions for a reset), the stale-context reminder of an acknowledged consumer, override priority, cancellation, native TUI review and viewer switch cleanup.
- Both profiles use `FIGLENS_BIN` pointing to the verified candidate binary. The same candidate's default wrapper cold path is checked separately by CLI/Pi tests; do not label a native override run as a cold adapter download.

The mapping case is original synthetic input generated at test time, not a Figma export or accuracy oracle:

```sh
mkdir -p samples/plugin-research/fixtures
docker compose run --rm dev cargo run --locked --example mapping-fixture -- samples/plugin-research/fixtures/mapping.fig
```

The generator refuses an existing output. CI's `host-installation` job starts it in the background while the host SDKs install, and never uploads the result. Public `examples/first-success/design.fig` remains the only distributable design fixture. Writer mocks, native synthetic parsing, real installed host/UI, image transport, actual model results and platform results are separate evidence. No-model acceptance never calls providers or reads user credentials/global plugins. Model plan/YOLO acceptance requires separate usage authorization; keep it untested until authorized. Local macOS acceptance does not prove Linux/Windows native TUI support or future CI success.
