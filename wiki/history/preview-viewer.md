# Read-only preview and agent handoff (2026-10-23)

## Changes and decisions

- Added `figlens preview <file.fig> [node]` with a loopback service and `--out preview.html` / `-o` snapshots. The existing native binary embeds the browser UI; users need no frontend build, Node, Figma or network service.
- Added page/frame browsing, visible-only thumbnails, stored name/text search, selectable expanded layers, bounds-based overlap picking, synchronized tree/breadcrumbs, zoom/pan, property/variable inspection and original-image downloads.
- Context and prompts retain exact selected IDs. Real bundles use existing assets/manifests/references; bundle CLI/MCP now also accept expanded instance sublayers without changing their result shapes. No project-code/component mapping was added.
- Screenshot comparison is a local, manually interpreted overlay or side-by-side view. It does not measure pixel accuracy. Reference/overlays use the existing renderer and its export-area origin; no second layout renderer or frontend framework was introduced.
- Live saves use timestamp/revision polling with visible stale/error states and selection restoration only for existing IDs. Portable HTML embeds one snapshot scope and its real bundle; selected-child context, asset downloads and comparison stay usable without a service. It does not pretend an embedded root bundle changes scope when a child is selected.
- HTTP actions, IDs, revisions, headers and output locations are constrained. Embedded JSON and DOM text handling keep malicious design names inert. The service is intended for private loopback use, not public authenticated hosting.

## Figma-style redesign (2026-10-23)

Requested directly by the user after the first viewer: light/dark themes and an experience as close to Figma as possible, accepted against `theme7-desktop.fig` (389 MB) and `theme7-mobile.fig` (403 MB).

- The canvas now shows each page's own layers at their real positions; sections render whole, frames/components/sections carry Figma-style names, Figma's `internalOnly` canvas and non-layer records are hidden, and a Layers panel replaces the frame list. Selection follows Figma (level click, double-click/Enter deeper, ⌘/Ctrl deepest, right-click picker, Esc clears), with Alt measurement, hover sync, a zoom menu, deep links (`#node=`), click-to-copy values, Dev Mode style CSS, an Export panel (PNG/JPG/WebP/AVIF, 0.5–4x), download confirmations and `window.figlens` for browser-automation agents.
- Performance work was measured, not assumed: buffered `.fig` ZIP reads (requests 0.19–0.42 s → ~0.01 s), one decode per revision, revision polling instead of re-downloading the catalog, base64 assets moved to an asset route (a 24.7 MB frame payload → 14 KB), tiered `view` renders capped at 8192 px, a worker pool (a 7.7 s export no longer blocks a 0.9 s data request) and a disk render cache (16 frames: 18.3 s cold → 0.02 s after restart) with `figlens cache [clear]` and a viewer menu to clear it.
- Sweeps rendered every top-level frame of both theme7 files through thumb, data and image routes: **744 + 527 frames, 0 failures**, median ≈0.01 s, p95 render 0.27–0.5 s, worst ≈2 s for frames holding ~10 MB images.
- Final checks: `cargo test` **62 library + 16 binary**, fmt and clippy clean, `scripts/preview.test.cjs` 3, npm 2, live browser acceptance **30 checks** (now including export, agent API, deep links, zoom menu, cache clearing, Figma selection) and offline snapshots 9 + 9 (Aurora, crafted script-closing name).

## Evidence and limits

Task-owned, ignored evidence is under `samples/preview/`: `final-rust.log`, `final-npm.log`, `final-frontend.log`, `final-browser.log`, `final-live/`, `refresh-results.json`, `security-results.json`, `mcp-frame.png`, `nucleus-large.png`, `aurora.html`, `mcp.html`, `crafted.html`, `offline-aurora/`, `offline-mcp/`, `offline-crafted/` and `offline-asset/`. These design artifacts are not committed.

Existing renderer gaps remain. Picking is axis-aligned bounds-based, comparison stretches to the reference dimensions, and no Figma accuracy sweep was claimed for the viewer. Save detection uses mtime. Renders persist on the local disk until cleared. Snapshots contain their design/assets and can be large. Browser acceptance used local Chrome, not every browser/OS or a screen-reader audit.
