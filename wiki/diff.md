# Diff

`figlens diff <old.fig> <new.fig>` and MCP `diff` (`old`, `file`) compare one stored scope (`--node`/`node`, default `0:0`) of two saved revisions (#81). The engine is `src/search/diff.rs`; durable changes (#92) are to reuse it, not build another.

## Build

Each side is a full relations build ([usages](usages.md)) through `build_with` with a facet collector, so ordinary search (text-only) and usages never pay for it. Per record it keeps, in `diff::FIELDS` order, each present effective field: the instance override (`Expanded.props`, or the expansion's size and matrix) else the stored field, the same rule as usages. A field's size is estimated first; past `VISITS` (65,536 visits) or an estimated 64 KiB (`FIELD_BYTES`) it is `unread`, never converted or scanned again. Otherwise it is converted to JSON (so a JSON override and the stored kiwi value digest alike) and streamed into SHA-256 over version, key, bytes and length, so escaping never buffers the whole value, followed by the raw bytes only when JSON shows some as `<N bytes>` (an override that already holds such a placeholder is unread), so an override equal to the stored value digests alike. Geometry and vector fields (`fillGeometry`, `strokeGeometry`, `vectorData`) digest the bytes of the blobs they name instead of the file-local blob index; a missing or malformed blob (`Tree::blob` reads compact bytes or an array of bytes), or one needing more than `VISITS` visits, makes the field unread; the value is kept only when it fits 512 bytes and the record's 4 KiB. A record with an unread field is listed with `unread`, never taken for unchanged, and counted in `unread_fields`. Every visit, byte and kept value is charged to the side's `Bounds` before it is kept. A side decodes, builds and drops its tree before the next side loads; only the two indexes with their facets stay.

Facets: `text` (textData, font fields and truncation), `layout` (size, transform, constraints, stack fields, clipping), `appearance` (paints, stroke weights, effects, opacity, blend, mask, visibility, radii, path geometry and vector networks), `properties` (component property assignments, refs, variant specs), `structure` (name, type, parent, sibling order, hidden; from the record, and for the selected node its stored parent and position, which the index's root leaves out; it is charged to the side's bounds before the build, and when it cannot be verified the side is partial with `selection_context_unknown`) and `bindings` (the record's edges compared as relation, target, state and evidence, so a removed edge is listed; an `instance_of` change adds `swap` with both mains).

## Matching and coverage

Records match by exact id within the selected pair, and the reply says `matching: {basis: node_id+kind, lineage: unverified}`: two caller-chosen files are never proven to be one Figma file. Same id with another type is `kind_changed` with `identity_uncertain`. A record missing on a side that stopped (`stop` set), or below a layer that side hides and left unexpanded (`hidden_content`), is `unknown`, never removed or added. Hidden layers either side left unexpanded (`hidden_content_not_expanded`) and links its index could not verify or read (`relation_unverified`) may hide changes, so each is a per-side coverage reason with its count and that side is not complete. An added or removed subtree is reported at its top record with `descendants`, except that the selected node's children are always listed, so `--node` drills into one. A selected node present on one side only leaves the other side empty and complete (`coverage.<side>.selected: false`); on neither side it is `node_not_found`. Removed and added top-level frames of one page that share a name, else the same rounded size and position, get a labelled `possibleMatch` (at most 200; each candidate is probed once and charged, and lookup keys are charged before they are copied); they stay removed and added.

## Paging and cache

Changes are kept once per pair as a compact list (frame, record indexes, facet bits). The id maps and sibling orders of both sides, every compared record's fields and edges, each change, frame and subtree entry are charged to a pair budget (`PAIR_WORK`, `PAIR_BYTES`) before the work; past it the reply is partial with `diff_work_limit`. Pages slice that list in frame order (100, 1-500), and each frame's summary counts the whole list, so a frame split across pages still reports its full count. A page spends at most 256 KiB (`PAGE_VALUES`) on names, frame headers, field values and edge entries: a value over it says `truncated`, edges over it are counted in `edges.truncated`, and once a page is full it ends early with `nextCursor` at the next change, so none is dropped; a first change that alone passes it is `response_budget`. Edge comparison costs one of `PAGE_WORK` visits per edge, checked with an estimated 64 set bytes per edge (`EDGE_SET_BYTES`, accounting only, not a measured heap cap) before the sets are built: a changed record whose edges do not fit ends the page before it, or is `query_work_limit` (with a `usages --out` next step) when it comes first. Edge differences are a set difference of both sides' edges, and the unread count is kept with the pair, so a cached page costs its listed changes plus their edge visits, not a scan of the pair. The cursor binds the version, both sourceIds, snapshots and built signatures (generation and stop) and the node; another pair is `cursor_stale`.

The process keeps one pair (`PAIR`), replaced when a call names other paths, stamps or node, rechecked against both stamps on every page and rehashed after `REHASH`; a deadline-stopped side is never cached. MCP pages reuse it; each CLI call is a new process, so a CLI cursor rebuilds both sides. MCP admits `old` like `file` (checked against `--root` on admission and every page); `gs://` sources are refused.
