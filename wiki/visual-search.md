# Visual retrieval core

`src/search/visual.rs` supplies raster comparison primitives; workspace `search` exposes them as image queries (below). Quality and performance acceptance remain tracked in #95. The `siglip-base` model profile and the model child's image requests are implemented ([semantic](semantic.md)). Exact SVG outline lookup remains `export::SvgIndex` and is a different comparison.

## Units and admission

`units` walks a full prepared `search::Index` under `expand::Bounds`, selecting screen kinds below pages/sections, component roots and explicit subscopes, in document order. It returns borrowed ids, record ids and visibility metadata. Hidden/internal flags are preserved for retrieval filters rather than dropping potential units during extraction. A render failure must be reported on that unit without removing its text record. A partial index or stopped walk never proves absence.

`QueryImage` admits PNG only: encoded bytes at most 8 MiB and decoded pixels at most 4,000,000, checked before decoding. The entry point must also bound its read to the byte cap plus one. Crops are positive integer pixel rectangles within the source. Crop before filtering, composite on white, aspect-fit to 256 by 256 with bilinear sampling; `visual-hash-1` pins this policy. Re-encoding the normalized raster strips source metadata. Query rasters remain request-owned and are not persisted by this module.

`render_unit` reuses the export renderer and original-image byte budgets, reading image paints from the same staged bytes used to decode the tree. It renders export bounds at at most 1024 pixels on the longest side, then applies the query normalization. It returns the export bounds and at most 200 known render/missing-image diagnostics, with a truncation flag. These diagnostics are not an exhaustive fidelity audit. File exports keep the same renderer path and behavior.

## Fingerprints and ranking

A fingerprint keeps the normalized pixel SHA-256 with reduced source aspect, 128 luma-gradient bits and mean RGB. Its fixed-size cache blob has an explicit version and rejects invalid dimensions. `visual-hash-distance-1` ranks equal normalized pixels first, then gradient, color, aspect distance and record order, retaining only bounded top-k candidates. Callers supply only authorized, filtered units from the requested generation. Work stops are partial coverage, cancellation is an error, and distances are not probabilities or component identity.

## Optional vision tower

The `embed` feature contains the CPU SigLIP vision tower at `google/siglip-base-patch16-224` revision `7fd15f0689c79d79e38b1c2e2e2370a7bf2761ed` ([model card](https://huggingface.co/google/siglip-base-patch16-224)). The loader verifies the pinned weight SHA-256, uses safe buffered loading and retains only vision tensors. Its policy adds bilinear 224 RGB sampling, scaling to [-1,1], pooled output and L2 normalization; this differs from the upstream processor's bicubic resize and has its own version. A batch holds at most four images.

`scripts/visual-preflight.rs` and `scripts/visual-reference.py` compare the tower's forward output against the offline transformers reference on identical normalized NCHW tensors, including batch/single parity. This is not upstream image-processor parity or retrieval-quality acceptance. `models configure siglip-base` records the vision profile, and its child's vectors through the image protocol equal this tower run in process on the same rasters (a local check on the pinned weights). Image queries and `index visual` use it (below); held-out quality, native performance and installed-host acceptance remain pending.

## Stored source rasters

Workspace schema 10 adds `visual_rasters` and `visual_units`. Normalized source thumbnails are content-addressed under the render policy; each generation retains its own record id, bounds, known diagnostics and render error. A failed render does not change its text record. Generation cleanup preserves shared rasters until their last reference is gone. Stored PNGs are capped at 300 KiB and evidence at 256 KiB per unit; a visual corpus holds at most 2,000 units. Query images never enter this cache. Only a visual job (`index` action `visual`) writes them.

Image-only requests reuse all text-search filter and cursor syntax limits but do not invent query text. A local query PNG is read from an already authorized canonical path through the registered-source no-link opener, checked as a regular file before and after open, and capped at 8 MiB before decode. Reads poll cancellation between bounded chunks. The normalized image remains request-owned; no temporary or cache file is created. Compact stored candidates carry only record id, raster key and fingerprint, so ranking does not load every thumbnail or diagnostic report.

## Visual jobs

`index visual <select> --scope NODE [--source ID] [--request-id ID]` (MCP `index` action `visual`; `jobs::visual`) submits a fenced job (kind `visual`) on exactly that published scope; the scope is required and never widened to the whole file. Code: `src/workspace/visual_job.rs`, `src/workspace/jobs.rs`.

- **Slot and lane.** Its key is source, scope, published generation, `visual::POLICY` and the active vision profile id, or `visual-hash-1` without one (`jobs_visual`, schema 10). It joins or blocks no text build and queues on `visual.lock`; a newer visual submit cancels an obsolete one. Its fence (same attempt, not cancelled, generation still published, membership and vision profile unchanged) is checked before each batch, so a newer publication refuses its writes. An interrupted one is retried as `visual`.
- **Worker.** Hash-only, figlens runs `__visual-worker` itself; with a vision profile, that profile's `figlens-embed` runs `__visual-worker` (`run_visual_worker` with an injected loader): one process, killed with its tree on cancel. It stages the registered bytes (their snapshot must be the generation's, else `source_stale`), builds the full index the same way the build did (`search::index_stored`) and checks each unit's record id against the stored records. `scope_units` adds the scope root below a page; hidden units and units on internal pages are skipped unless one is that root; at most 2,000 units (`visual_capacity`). One job's render budget is 10 minutes and 2^30 rendered pixels, charged before each unit; reaching it stops with `render_budget`, layer `partial`. Rasters this generation already stored from this renderer (`visual::RENDERER`, the figlens version, kept in each unit's report, a render error's included) are kept; only they rank or are embedded. A render error stored before errors recorded their renderer reads as another renderer's, so its layer is `stale` once. A resume renders units never rendered before this renderer's failures, so a unit that keeps failing cannot take a new unit's budget. A reference (`imageRef`) reads its stored render as is.
- **Layers.** Units commit 8 per batch; the hash layer is published `ready` or `partial` as soon as rendering ends, and a `ready` hash layer of this renderer is never written again, so a vision failure fails only the vision layer. An explicit `index visual` on a `partial` one keeps its current rasters and renders the rest again, render errors included. `model_layers` row (gen, `visual-hash-1`, `POLICY`): `chunks`/`texts` units, `embedded` rendered, `refused` render errors. A render error is that unit's `error` and makes the layer `partial`; the job still succeeds. The tree and bytes are dropped before the model loads. Vision vectors: `model_vectors` (profile id, `raster_key`), `model_refs` (gen, profile id, `POLICY`, `raster_key`) for units rendered by this renderer only, and a vision layer row. `raster_key` is SHA-256 of the policy and normalized fingerprint, a different domain from text hashes, and vectors are per profile, so a stored vector is reused only for identical pixels under the same profile and policy; a rebuild loads no model. Batches hold at most 4 images and commit with progress. A failed or cancelled job (a dead owner's cancel included) marks the layers it left `building` `failed`; readers (`visual_search::layer_state`, workspace semantic search) also read a `building` layer whose job ended or lost its owner as `failed`, and a finished layer with a unit (raster or error) of another renderer as `stale`; both name the `index visual` step, as does a vision layer not yet built.
- **Auto-queue.** Only a scope that wants a layer: a retained generation of it has a hash layer row in any state, or a visual job of it is queued, running or interrupted. Its generation has the layer when the hash layer, and the vision layer when a vision profile is configured, read `ready` or `partial`. Then the MCP server and the watch runner submit `visual` after a text build publishes and run it on their model lane or thread; the one-shot CLI lists `index visual` in `nextSteps`. No scope is rendered unless `index visual` was run for it once.

## Image queries

`workspace::query::search_image` (CLI `search --workspace|--file|--id --image PNG|--image-ref JSON [--crop x,y,w,h]`, MCP `search` `image`/`imageRef`/`crop`) ranks a workspace's published visual units. A stateless `.fig` search refuses an image and names `prepare` then `index` `visual`; a query never creates a database or a layer. `image` and `imageRef` are exclusive. A local path is admitted against MCP roots like any other path, rechecked before the read, and never echoed (`query.image.kind` is `path`); URLs are refused. A crop on a local PNG is in its pixels; on a reference it is in the stored 256 by 256 thumbnail's pixels, and without a crop the stored fingerprint and aspect are used as is.

An `imageRef` `{sourceId, snapshotId, nodeId}` is resolved apart from the result filters and the searched scope: the requested scope's published generation first, then the source's other published scopes in order (at most 64), each only when the caller sees the source, it is ready and fresh, and it serves exactly that snapshot. Another snapshot is `source_stale`; a node with no stored raster names the `index` `visual` step. The viewer's thumbnail (`reference_image`) uses the same resolver.

Modes: an image alone is `visual`; with query text it is `hybrid` (an image with `mode: "hybrid"` and no text is allowed); `visual` with text and `text`/`semantic` with an image are invalid. Filters (`type`, hidden, internal, sources, scope) apply before any channel ranks. Each channel ranks across every selected source at most 200 candidates, and the lists are fused once by the versioned RRF of semantic search (`visual-rrf-1`), never per source. Channel policy: when every searched source has a ready vision layer under the active visual profile, `visual_embedding` (cosine of the query's SigLIP vector against stored unit vectors) is the approximate signal and `visual_exact` adds only exact normalized-pixel copies; otherwise `visual_hash` is the whole model-free ranking. Hybrid adds `text` and, with a ready text model layer, `semantic`. This policy is **quality pending**: root's diagnostic found equal-weight hash and vision fusion ranked crops and background changes worse (wrong top-1), and the fixed policy has not had independent held-out validation.

Each match keeps its channel's basis: `lexical` spans only for text hits, `semantic`, `normalized_pixels`/`perceptual_hash` with distances, `visual_embedding` with its cosine. `query.usedModes` and `ranking.channels` list the channels that ran; `coverage.layers.visual` reports the hash and embedding states per source and which signal was `approximate`. A model that is not configured, pending or fails (`runtime_failed`) leaves the hash ranking and says so; it is never reported as visual success through text alone. A source without a ready visual layer makes the page partial with an `index` `visual` step; a `partial` layer keeps it partial and names that step only when its render budget stopped it, since a rerun resumes it; render errors and the unit cap name none, and nothing retries them automatically. Each shown row carries `visual` `{state: rendered|failed|absent, bounds, diagnostics, diagnosticsTruncated, error}` read for that row only and counted toward the search reply budget (`response_budget_exceeded`: lower `limit`). Cursors bind the query image digest, crop, profiles, channels, filters and generations; a partial page has no `nextCursor`. The text and the image model each keep one warm child, so a hybrid search restarts neither; cancellation stops the vision child. The query image is read once and never written.
