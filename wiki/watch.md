# Watching

`watch start|stop|status` (`src/workspace/watch.rs`; CLI `figlens watch run|status`, MCP `watch`) refreshes leased scopes on each save without an index call. Schema 5 adds `watch_leases`, `watch_runner` and `watch_monitor`; changes/usages still read schemas 4 and 3 without migrating.

- **Leases.** `start` needs the scope tracked (`active` or `baseline_pending`) and inserts one lease for this holder process (an MCP server or `watch run`) at the scope's tracking `epoch`: random `leaseId`, TTL 30 s, `requestId` replays this holder's live lease and reports an ended one, never restarting it, for `KEEP_ENDED_MS` (1 h) after the end among the newest `KEEP_ENDED_ROWS` (1024) ended rows, about 300 B each; past either bound it is unknown and starts a new lease, as a job's requestId does once its job is collected. A requestId of another live holder's lease is refused. A lease whose scope was untracked or retracked since its start ends (`untracked`) at its holder's next renewal or replay, so it never keeps a runner or `watch run` alive. `start` chooses and authorizes the source inside its IMMEDIATE transaction, so a relocation lands before or after it, never between the roots check and `authorized_path`. The runner's refresh is admitted through `jobs::refresh_fenced`, whose fence (a lease still serving that path) is read inside the submit's IMMEDIATE write before any replay, join or new job, so a relocation lands wholly before it (nothing admitted, joined or cancelled) or after it (and cancels the stale build itself). Caps: 64 live per workspace, 16 per holder, 16 sources. A holder renews all its leases in one UPDATE every 10 s, rechecking each source path against its own roots (`authorized_path`; a path it no longer sees makes only its lease `unauthorized`). Between renewals the registered path is the authority: it is canonical, so the runner never stamps through a link swapped in at it or above it (`storage::leads_to_itself`), and every job reads a source only through `storage::staged`: on Unix it opens the path one component at a time from `/` with `O_NOFOLLOW` (search-only `O_PATH`/`O_SEARCH` directory handles, so execute-only parents stay readable; a nonblocking regular leaf), and on Windows it checks the handle's `GetFinalPathNameByHandleW` against the path before reading, so a link at it or above it, swapped in before or during the open, is refused (`SourceUnreadable`, relocate the source). Size and time come from the opened handle, and a save racing the read is retried. A source prepared through a link is registered as its target, so saves to that file are followed. `stop` ends one of the caller's leases; MCP input end or SIGTERM/SIGINT/console Ctrl-C (OMP signals right after closing stdin; a thread blocked on a close-on-exec socket pair (made before the handlers are installed, so a failure stops the server before it serves; only the first signal writes, nonblocking), or on Windows a condvar, wakes only then, sets `CLOSING` under `HELD` so a start not yet held rolls back, and the server exits 143; release is best effort: a crash or forced kill on any OS before the release commits, such as Windows TerminateProcess or OMP 18.13.2's SIGKILL 1 s after its SIGTERM while the release waits up to 5 s on a write lock, leaves the leases to lapse in 30 s) and `watch run`'s stdin EOF, signal or unwritable lease line end all of the holder's (`released`), and a holder that ended the workspace's last live leases waits up to 2 s (`CANCEL_WAIT`) for the runner to exit. Each renewal pass renews every workspace before it restarts any runner, and rewrites only the authorization of sources it read, so a lease started meanwhile keeps its own. A crashed holder's leases lapse within 30 s. A renewal that finds none of the holder's leases (all ended, or the workspace reset or removed) forgets that workspace, so MCP's renewal thread parks again and `watch run` prints its lease's end and exits. Source removal ends its leases (`source_removed`); an untrack makes them `untracked` for good, since a later track starts a new epoch. MCP's renewal thread parks until a start, so a server that never watches touches no database. `index reset` ends every lease (`reset`) before it takes the exclusive lock, so the runner exits instead of making it busy.
- **Runner.** One per workspace: hidden `__watch-runner`, holding `watch/runner.lock` and taking `attempt + 1` in `watch_runner`; every runner write rechecks token and attempt. A holder starts it through `__watch-launch`, which exits, so the runner is not in the host's process tree (unix: own process group; Windows: `CREATE_BREAKAWAY_FROM_JOB`, else placement `in_host_job`, which dies with the host's job and is restarted by the next renewal). It reads the served lease union every 250 ms poll over one read connection it keeps open (with the workspace's shared lock, never an open transaction; each persist ends with a passive WAL checkpoint, since no close does) (live, authorized, of the current epoch and `active`: nothing is refreshed while a baseline is pending), polls each covered source (`Detector`: 250 ms stat, 300 ms stability window up to 1.2 s, a changed stamp probed again exactly at that deadline, the loop sleeping until the earliest probe and at most 250 ms; content check every 60 s, busy backoff to 5 s; a failed refresh, or one that ran no job, retries after 5 s and is never credited as verified, nor is a result for a path the source has since left; a scope newly served on a watched source refreshes it at its next stable stamp, not the next 60 s check) and refreshes one source at a time, in arrival order (a source waiting for the worker runs before another follow-up of a busy one), rechecking each scope's lease right before its submit. A job another process runs is awaited, never run or cancelled; the source is verified only when every job `succeeded`. Every refresh stages and hashes the bytes, so a same-stamp save publishes only if the bytes differ. Any end of its loop, an error included, runs the shutdown. When no live lease is left it sets `closing` in one IMMEDIATE transaction that rechecks the leases, submits nothing more, cancels its own attempts with `jobs.shared = 0` and finishes shared ones: a join, requestId replay or takeover sets `shared` in its submit transaction (`jobs::share`); any new join path in `submit` must call it too, or the runner cancels a job another caller waits on. A start seeing a `closing` runner waits (up to 10 s, else `stopping`) and starts the next. A start whose runner fails to launch or say ready ends the lease it created (`start_failed`), never a replayed one, and returns the error; ready lines are capped at 64 bytes and 10 s, and an unknown lock state is `unknown`, never `running`. After a refresh it publishes, it also submits that scope's `embed` when a model profile is configured and runs it on its own thread; an exit cancels it only when no other caller joined it ([semantic](semantic.md#workspace-layer)).
- **Saved queries.** The union read also returns each served scope's published `gen`; a scope that appears or whose `gen` changed (any publisher) is due from the start (`changes::evaluate_published` with no continuation), dropping an older one. The worker runs one bounded turn at a time, round-robin, only while no refresh runs or waits; a queued refresh or shutdown sets the turn's cancel flag, and a cancelled turn resumes from its unchanged continuation. `WorkspaceBusy`/`StorageUnavailable` retries after 2 s; other errors are logged to stderr and dropped, while `evaluate_published` notes its own search and record failures as `eval_failure`. Continuations live in memory, so a restart recomputes them. Debug `FIGLENS_TEST_WATCH=turn_holds:<file>` holds a turn until it is cancelled and writes `<file>.reached`.
- **Monitor.** `changes.monitor` is `inactive` unless a live lease on `active` tracking covers the view (what the runner serves), `partial` when every leased part is watching but a tracked scope of the view has no lease authorizing its path, then the first non-`watching` state across its sources: `unauthorized`, the runner's `source_busy|source_missing|source_unreadable` or `refresh_failed` (two refreshes failed running, until one succeeds; the error itself is not reported) (busy, then unreadable, also for a path now leading elsewhere through a link, which only `relocate` resolves), or `stale` (runner lock free, or its row, and with none yet its beat, older than 30 s); monitor rows are never written for a removed source; with the poll/verify/persist cadence and `stampCheckedAtMs`/`contentVerifiedAtMs`. `tracking.state` is separate: tracked but unwatched is `inactive`. An empty page never proves the disk unchanged.
- **status** is read-only (leases the caller sees: `active`, `unauthorized`, `untracked`, `expired` or `ended`; runner `running`, `stopping`, `stopped` or `unknown` with placement); it never reclaims or writes, not even an owner file (`mine` is true only in the process that holds the lease). It reads the visible sources and their leases in one snapshot and filters to them before its bound of 256 rows, lists live leases before ended ones, and sets `truncated: true` when older ended rows are left out.
- **Limits.** Detection is polling, not file events. A watch lives only while a holder runs: a host whose MCP server is stopped between turns, or that never calls `watch start`, gets no automatic refresh, and its `changes` shows `monitor: inactive`. Native Windows placement is checked only by `check_watch` in the Windows installation job (see `installation`), not yet measured.
- **Gates** (Dockerfile.dist candidates from 9b58b70 on a shared, contended host, load 2.7 to 5.8; not a capacity gate for many saves or cancels). Native macOS arm64 release: placement `independent` (PPID 1, own group); the last holder's stdin close to runner exit p50 255, p95 289, max 289 ms (20 samples); idle per 60 s the runner uses 56 to 62 ms CPU and about 460 KiB of writes with 1 or 8 holders, 3.5 MiB footprint. `check_watch` (one sample each, macOS native and Linux musl in Docker): a save reaches `changes` in 954 and 831 ms, a killed runner is restarted by the next renewal 9.0 and 9.4 s later, and the last EOF stops it in 13 and 64 ms. Earlier Docker Linux gates (release idle p95 301 ms; debug with the runner's own job held, p95 338 ms) measured older commits. Windows is checked only by `check_watch` in CI and not yet measured. Test hooks: `FIGLENS_TEST_HOLD=watch_closing:<file>` holds a closing runner, and `watch_start_closing:<file>` a start that sees it; debug `FIGLENS_TEST_WATCH=launch_fails|runner_silent` with `FIGLENS_TEST_WATCH_READY_MS` fail a start, and `union_fails:<file>` fails the runner's lease read while the file exists. `FIGLENS_TEST_HOLD` stages `watch_admit` (a start's source chosen, inside its transaction) and `watch_status` (status's visible sources chosen) stop there while the file exists.
