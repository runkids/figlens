# Herdr panel

Load this when changing the figlens mod or layout for [Herdr](https://herdr.dev) under `herdr/`. The [user walkthrough](../herdr/README.md) owns install and use; the [mod recipe](../herdr/figlens/RECIPE.md) and [layout recipe](../herdr/figlens-layout/RECIPE.md) describe what a build must do, and [`herdr/AGENTS.md`](../herdr/AGENTS.md) holds the folder's rules.

## Shape

- `herdr/figlens/` is the mod as shared at herdr.dev/mods; `herdr/figlens-layout/` is Herdr's `main` layout plus a tab-bar toggle and the panel in the side `panel-body` stack, with an identical copy of the mod. Tests in `herdr/tests/` run in `npm test` and CI (`test.yaml`) and check the copies match.
- The mod is a client of the CLI: it calls `tree`, `export` (`--frames`, `--bounds layout`, `--scale`, `--max-size`), `inspect`, `find`, `diff --node` (Changed since built), `preview`, `cache` and the release download, all through `env -u HC_TERMINAL_ID` so its own calls never journal, never the MCP server, and it reads the [activity journal](#activity-journal)'s `v: 1` lines. A change to those commands' output shape or to the line format can break it; run `node --test herdr/tests/*.test.mjs` and `herdr-app check herdr/figlens/mods/figlens`.
- It runs figlens on the machine that holds the design (Herdr's `exec` with `on`), so a remote design never moves for reading. Only images (thumbnails as one tar.gz per batch, previews, snapshots) come back.
- It hands work to the agent focused on the left through `hc send`, after a confirm dialog that shows the exact message. Pi and OpenCode get their own `/figlens plan` and `/figlens yolo`; Claude Code the figlens MCP tool `workflow` with that topic, named as figlens's (Claude Code has its own Workflow tool) and with `<cli> workflow <topic>` for a session without the figlens MCP server; others a plain prompt naming the skill's `references/planning.md` or `references/yolo.md`. OMP gets the plain prompt because its extension does not dispatch plan or yolo. Keep these strings in step with those hosts' commands and the skill's reference paths (`frames.js` `intentText`, tested).

## Activity journal

Inside a Herdr terminal (`HC_TERMINAL_ID` set: `t7` here, the terminal's local id on another machine), `figlens mcp`, and the CLI's node-reading commands (below), append one JSON line per successful call that read the design's nodes (`src/activity.rs`, from `execute` in `src/mcp.rs`: `tree`, `inspect`, `nodes`, `variables`, `export`, `export_batch`, `bundle`, `compare_image`) to `<state>/activity/<key>.jsonl`. `find`, `search`, `usages` and `diff` are searches and are not recorded, so "stores nothing" in the host docs stays true of them. Agents need no guidance for it (they do nothing differently), so the skill and MCP instructions do not mention it.

- `<state>` is the default state folder (`Storage::state_dir`), whatever `--storage-root` says, so a host finds it. `<key>` is the first 16 hex digits of the SHA-256 of the path figlens resolved: canonical (symlinks resolved, `/private/var` on macOS); for `gs://` the cached snapshot's path.
- A line: `{"v":1,"at":<ms>,"terminal":"t7","tool":"inspect","file":"<path>","nodes":["12:3"],"screen":"12:1","box":[x,y,w,h]}`. Ids are normalized (`12-3` and Figma links become `12:3`) and anything else is dropped, so a link's file key and name never reach a line; at most 20. For one id, `screen` is the top frame that holds it, as `tree --top-frames` names screens, and `box` its layout box there; a layer inside an instance (`I12:3;45:6`) gets its outermost instance's screen and no box. The line carries the design's path; no names, text or images. Each line also carries `revision`, the design's saved version as `stat` prints it (`<modified seconds> <bytes>`, `activity::revision`). A `compare_image` line adds `result`: `mismatch`, `nonTextMismatch`, `regionCount` and the paths of the compared `screenshot` and the written `diff` (`compare_summary`), numbers and project paths only.
- A file over 256 KiB moves to `<key>.1.jsonl` first, best effort: two servers rotating at once may lose the older history, never more than about 512 KiB per design. Each line is one append, so servers may write at once. A failure is reported once on stderr and never fails the call. Starting a new journal removes those untouched for 7 days (a design copy gets a new key per saved version). Delete `<state>/activity/` to clear it.
- Outside Herdr nothing is written. Inside it, the CLI's node-reading commands write the same lines (`journal_cli` in `src/main.rs`: `tree`, `inspect`, `node`, `nodes`, `variables`, `bundle`, `export` recording the command's own node as parsed (`Command::node`, never a flag's value such as `--mode 1:0` or `--compare`; none for `variables` of the whole file, as MCP) and naming the tool as MCP does (`compare-image` is `compare_image`, `node` is `nodes`), `compare-image` with its result; batch forms and `find` write none), so an agent that runs figlens in its shell, and OpenCode's CLI-path tools, show too.
- Overhead: 200 warm `inspect` calls of a depth-16 node through one release-build server on a 15,480-node design, median per call, journal on vs off, three rounds: no difference above noise (about 2.5 ms either way).
- Hosts: Claude Code passes `HC_TERMINAL_ID` to the servers it starts (five servers under Herdr on macOS). Codex, Pi, OpenCode and OMP were not checked; figlens's adapters pass the host's environment through, but a host that filters it (Codex's `env_vars` pass-through list) must pass `HC_TERMINAL_ID`, or its agents leave no lines. No fallback: a terminal's id is not in the process tree.

The panel reads, every 5 s, each terminal's and each screen's newest line, each screen's newest comparison and the last 40 lines (`ACTIVITY`, an `awk` over the journal and its rotated half; `parseActivity`, `screenStates` and `recentActivity` in `frames.js`) on the design's machine and each machine with agents: for the design's path on its own machine, and for its copy on the others (`~/.cache/figlens/herdr-designs/<key>/`). A terminal there is addressed as `<machine>/<id>`. The copy is the current saved version's: after a save, an agent still reading the older copy shows again once the design is handed over again. The shell reads an absolute `XDG_STATE_HOME` from Herdr's environment; one set only in a shell rc file that Herdr does not see hides the lines. Previews are exported with `--bounds layout`, the space the boxes are in. Lines from the last 10 minutes of live agents show as a strip under the toolbar (screen and page; click opens that screen in Quick Look, watch-only, where the agents' boxes move as they read: the panel publishes each design's live lines to shared `figlens.live.v1`, `{ "<machine>:<path>": { at, entries } }`, each design dropped 10 minutes after its panel last wrote it), dots on screen rows and their page rows (also folded), and boxes on the preview, one color per agent.

The Board (List | Board in the header) groups the screens with `boardState` (`frames.js`) over `screenStates`: `building` while an agent used a building tool on it (`bundle`, `export`, `export_batch`, `nodes`, `variables`, `compare_image`; an `inspect` alone, such as Point's question, is a read) in the last 30 minutes after its last comparison, `verified` once `compare_image` ran on it, `read` for other reads, else not started. Each handoff the panel sends (Build, Plan, YOLO, Fix, Update after the confirm, or a new tab) is recorded per screen (a layer's screen) in shared `figlens.handoffs.v1` with its intent and its agent (address, or the new tab's name and space; Point is not recorded), for 7 days. The panel's 5 s poll moves each on with `handoffStep`: the agent's address once found, `started` once it works or waits, `finished` once it stops after that, is gone, or never started within 2 minutes; a finished handoff stays finished, so the agent's later turns on other work leave the screen alone. A handoff newer than the screen's comparison decides (`boardState`): building until finished (needs you while blocked), then `planned` for a plan or `done`, until a comparison, a newer handoff, or a newer build in the journal (another agent's, or any after it finished). Without one, a building screen follows the agent that built it: done once it stopped, read before once it is gone. Its Compare window copies the screenshot and diff (journaled as absolute paths) from the comparing agent's machine into the panel's cache, in parts from another machine, reads the size from the PNG header and renders the design; an older Verified row shows whatever diff file is at its path now, since compare_image writes `--out` where the agent says; Ask to fix sends `intentText` intent `fix` after the confirm. Picked screens (built when every pick is planned, else planned: the footer sends one intent) go to the agent on the left in one message (`intentText` with `targets`, one at a time; the only choice for one screen), or each in a new tab opens the new-tab dialog with `frames`, one tab per screen, the design copied once (the only choice with no agent on the left). Changed since built: on each load the panel keeps that saved version (`KEEP_REVISION`: a copy-on-write clone under `~/.cache/figlens/herdr-revisions/<key>/`, newest 8 per design, made only while the file's `stat -L` still matches and dropped if a save lands during the copy). When a screen's newest line on the design's machine read an older revision that is kept (a revision must match `isRevision` before it reaches a shell), the panel runs `figlens diff <kept> <design> --node <screen> --json` once per pair, one at a time (each decodes both designs; a whole large file stops at diff's work limit), and `scopeChange` takes any changed layer under that scope (diff files a screen inside a section under the section). The screen becomes `changed`, ahead of the other states, with its layers and facets. The board lists it first with Send…, and a banner names the newest one (Later puts it off for this saved version); both send `intentText` intent `update`, to the agent that worked on it while it runs, else the one on the left, after the confirm. Not caught: changes inside a component's definition (diff does not compare definitions), screens an agent read through a copy on another machine, and versions saved while no panel had the design open. Read before (an older read, no comparison) keeps such screens out of Not started.

## Rules

- `VERSION` in `engine.js` (both copies) is bumped by Release Please through a `generic` extra-files entry that rewrites its marked line; a test checks it equals `Cargo.toml`'s. Between merging the Release PR and running Publish Release, `main` names a version whose assets are not published yet, so the panel's one-click download fails for anyone who installs from `main` in that window; a figlens already on PATH or in the npm cache still works. The engine downloads that release's archive and checks it against its `SHA256SUMS`, like the npm launcher, and shares its cache (`~/.cache/figlens/npm/<version>/`).
- Large transfers go in parts: a remote command's output stops at 8 MB, `hc file write` at 8 MB, `hc put` at 16 MB, and a mod's own file writes are capped. Snapshots and design copies move through `hc exec dd` in 4 or 6 MB parts written by the shell.
- A design copied to another machine for an agent goes to `~/.cache/figlens/herdr-designs/<key>/` there, once per saved version; the cache row's clear removes it, and the versions kept for Changed since built (`herdr-revisions/`, named apart in the confirm), with the panel's images and `figlens cache clear`.
- Preview pictures are real screenshots in English, of a public or synthetic design.
- Not on Windows: the engine, discovery and transfers use `sh`.
