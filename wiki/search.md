# Search

Bounded ranked retrieval over effective instance content (issue #89). Load the `fig-format` topic too when the change touches expansion itself.

## Index and retrieval

- `src/search.rs` indexes one stored scope's effective content before retrieval: `expand_instances_bounded` applies the same overrides, text/boolean properties, swaps and stored-child precedence as REST, and the walk takes `tree.children` before `ex.children` so expanded and stored children never both count. Records carry exact ids, stored/instance-effective origin, `textSource` (stored, override, component default), page, `scopeRoot` and path. Text is NFKC, Unicode default case folding, NFKC, each applied to a whole segment so folding can compose across it: a segment starts at each character whose compatibility decomposition begins with a starter that cannot compose backward, so spans stay on their own originals while marks and jamo (conjoining or compatibility) still compose; a field with more than 1024 consecutive combining marks stops the build with its own reason `combining_run_limit` (`limits.combiningRun`) before normalization, since NFKC buffers each such run; tokens split on whitespace, punctuation and `/`; fields also index camel-case parts beside the whole word while queries keep whole words, so case folding alone decides a match; CJK as single characters plus bigrams; no simplified/traditional or kana equivalence. Ranking `lexical-1`: exact name, name phrase, text phrase, then BM25F (name 2, text 1), then document order. Builds charge estimated extraction and indexing costs (visits plus copied and retained bytes, including each property assignment a reference may copy, each copied layer name, every id string an expanded node keeps (its id twice, source and prototype source), the name and ids an override patch keeps beside its props, the instance-path prefix written into every merged override, derived and property-bound key, and each record's normalized copies and terms at their real size, since NFKC can expand a character many times over) to the shared `expand::Bounds` before that work, with preflight guards; the byte budget is an estimate, not a cap on process RSS or on every allocation. Placing each top-level instance walks its ancestors and is charged per step, and visibility is inherited in the one tree-order pass. Expansion leaves an eighth of work and bytes to indexing, so its stop still indexes stored layers; a build stop is a `partial` coverage reason, never absence. A reply refusal is separate: the estimated bytes a page's results copy (names, paths, a snippet capped at 2 KiB whose extension over attached characters stops at 32, and a fixed share for refs and spans) are counted against an 8 MiB budget (`limits.replyBytes`, CLI and MCP alike) before any result is built, and an over-budget page fails with `response_budget_exceeded` instead of returning partial coverage. MCP's check of the complete serialized reply, including escaping, stays separate. The snapshot is the SHA-256 of the staged `.fig` bytes; one index per process is reused while path, scope and stamp match and the file opens, rehashed after 60 s. Cursors bind source, snapshot, index generation, query, filters and ranking. Hidden instances and hidden sublayers are not expanded (REST omits them), so `includeHidden` reports `hidden_content_not_expanded`.
- A workspace stores each build as a generation ([index](index-jobs.md)) and searches it without parsing the `.fig`: `search::store` keeps records and per-term postings; `corpus_rank` computes corpus statistics and tiers over every survivor of every source before the global top-k, then `corpus_page` builds only the shown page. Results equal the stateless search of the same scope.
- Limits: 10M work, 512 MiB estimated bytes, 64 MiB indexed text, depth 256 and a 15 s deadline per build. Expanding a 179 MB held-out file charged 7.1M work and about 394 MB, and indexing it 139k work and 35 MB; budgets that no longer fit such a file need new measurements, not a silent raise.
- `scripts/measure-search.py` measures cold CLI search against `tree --depth 0`, the MCP first call, warm calls and peak RSS (Windows: working set) on one approved input (with `--usages ID` also stateless and workspace usages and `--builds N` index rebuilds); it reports shapes, not design names or text, but echoes the caller's queries and node, so a report on a private file stays private under `samples/`. Legacy `find`/`tree`/`inspect`/`nodes` must keep identical output hashes against the base binary.
- Saved-query subscriptions store `corpus_ranking()` and the normalized phrase, terms and types (`Prepared::phrase`/`terms`) with each evaluation: bumping `RANKING` or the tokenizer makes their next evaluation `ranking_changed` (`rankComparable: false`) or, for a changed normalization, `query_changed`; see [subscriptions](subscriptions.md).
