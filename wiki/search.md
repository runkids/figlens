# Search

Bounded ranked retrieval over effective instance content (issue #89). Load the `fig-format` topic too when the change touches expansion itself.

## Index and retrieval

- `src/search.rs` indexes one stored scope's effective content before retrieval: `expand_instances_bounded` applies the same overrides, text/boolean properties, swaps and stored-child precedence as REST, and the walk takes `tree.children` before `ex.children` so expanded and stored children never both count. Records carry exact ids, stored/instance-effective origin, `textSource` (stored, override, component default), page, `scopeRoot` and path. Text is NFKC, Unicode default case folding, NFKC, applied per segment: a segment starts at each character whose compatibility decomposition begins with a starter that cannot compose backward, so spans stay on their own originals while marks and jamo (conjoining or compatibility) still compose; a field with more than 1024 consecutive combining marks stops the build with its own reason `combining_run_limit` (`limits.combiningRun`) before normalization, since NFKC buffers each such run; tokens split on whitespace, punctuation and `/`; fields also index camel-case parts beside the whole word while queries keep whole words, so case folding alone decides a match; CJK as single characters plus bigrams; no simplified/traditional or kana equivalence. Ranking `lexical-1`: exact name, name phrase, text phrase, then BM25F (name 2, text 1), then document order. Builds charge estimated extraction and indexing costs (visits plus copied and retained bytes, including each property assignment a reference may copy and each copied layer name) to the shared `expand::Bounds` before that work, with preflight guards; the byte budget is an estimate, not a cap on process RSS or on every allocation. Expansion leaves an eighth of work and bytes to indexing, so its stop still indexes stored layers; a build stop is a `partial` coverage reason, never absence. A reply refusal is separate: a page's result names and paths are counted against an 8 MiB budget (`limits.replyBytes`, CLI and MCP alike) before any result is built, and each snippet as it is copied (snippets extend over at most 32 attached characters), and an over-budget page fails with `response_budget_exceeded` instead of returning partial coverage. The snapshot is the SHA-256 of the staged `.fig` bytes; one index per process is reused while path, scope and stamp match and the file opens, rehashed after 60 s. Cursors bind source, snapshot, index generation, query, filters and ranking. Hidden instances and hidden sublayers are not expanded (REST omits them), so `includeHidden` reports `hidden_content_not_expanded`.
- Limits: 10M work, 512 MiB estimated bytes, 64 MiB indexed text, depth 256 and a 15 s deadline per build. Expanding a 179 MB held-out file charged 7.1M work and about 394 MB, and indexing it 139k work and 35 MB; budgets that no longer fit such a file need new measurements, not a silent raise.
- `scripts/measure-search.py` measures cold CLI search against `tree --depth 0`, the MCP first call, warm calls and peak RSS on one approved input; it reports shapes, not design names or text, but echoes the caller's queries and node, so a report on a private file stays private under `samples/`. Legacy `find`/`tree`/`inspect`/`nodes` must keep identical output hashes against the base binary.
