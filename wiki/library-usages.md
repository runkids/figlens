# Library usages

Field reference linked from [usages](usages.md): how a stored generation keeps library references and how `usages` with `library` reads them across a workspace.

Library references (#93): a stored generation (`search::index_bytes`) and a stateless full build (`search::loaded` with relations, never a text-only one) keep `uses_library` edges in `Record.library`, off `Record.edges`, so edge readers match builds that skip them (viewer, diff); `store::add` never loads them, only `Graph::library` for one record. The target is the JSON array `[kind, namespace, key]` (kind `component`, `style` or `variable`), so strings cannot collide. The namespace is `sourceLibraryKey` from a cached copy, basis `cached_copy`: a main's own copy (evidence `{"copy": id}`), or for a style or variable assetRef the copies carrying its key (evidence `{"field", "version"}`). References carry no namespace, and a file's own definitions carry no key (keys are server-assigned), so this proves no definition identity. No namespace, no copy or disagreeing copies give `namespace: null`, state `unresolved`; `external` means only that a copy names the namespace. `usages::libraries` charges every node visit and kept key before the scan, and a scan that runs out stops the build.

Library query (`workspace/library.rs`): `usages` with `workspaceId` and `library {kind, namespace, key}` (CLI: a workspace selector plus `--library K --namespace NS --key KEY`) reads that exact target in every visible source's published `scope` (`sourceId` narrows to one), sources in added order, then `(rid, seq)`. MCP refuses `file`, `node`, `resource`, `snapshotId`, `relation` and `direction`; a relocated CLI `--file` gets a workspaceId recovery. `definition` is always `{state: unresolved, reason: library_source_unproven}`. Each result carries `hidden`, `internal`, `page` and `scopeRoot` from the stored record and the generation's page/root lists, read once a source shows a visible use, their UTF-8 bytes charged to the page before they are copied; no `path`, which would walk ancestors. A page holds 3 MiB of serialized results and coverage, so MCP's text and structuredContent copies fit its 8 MiB cap: `coverage.sources` and up to four copies of each source id in reasons are charged first (coverage alone over the page is `response_budget_exceeded`, asking for `sourceId`), and each use is checked in UTF-8 bytes (`length(CAST(… AS BLOB))`) before it is copied and as serialized after; a later use that no longer fits ends the page with a cursor, one that cannot fit an empty page (beside its source's page and root lists) is `response_budget_exceeded`, whose recovery repeats the question with that `sourceId` (unless one was given) and names the use for `inspect`. `coverage.sources` gives each source's path, state, nextSteps and, when ready, freshness as search reports it (`verifiedAtMs`, `stampCheckedAtMs`, size and modification time equal to the verified snapshot; no hash now). An unreadable file is reported before any not-prepared or pending state; reasons `source_not_ready`, `index_partial` (stopped build, unread fields or an unkept reference), `namespace_unknown` (the key with a null namespace), `hidden_excluded` (not incompleteness) and `authorization_restricted` (sources outside the roots, unnamed). Cursor `l1.<fingerprint>.<source>.<rid>.<seq>.<gens>` binds the reference, scope, includeHidden, sourceId, versions, visibility and each source's state, all `cursor_stale` when changed and checked before any generation is looked up; `<gens>` carries each source's generation (`n` when not ready), so a reindexed source is `cursor_stale` while its old generation remains and `cursor_expired` once it is deleted, each checked against that source's own id. The cursor's length is bounded by the source count before it is split.

Naming one: outgoing `usages` (`direction: out`, CLI `--out`) adds `library {kind, namespace, key, basis: cached_copy}` to an `instance_of`, `uses_style` or `binds_variable` result whose record keeps a reference for the same copy (`evidence.copy` = the target) or field and key (`usages::library_of`), stateless and stored alike; a null namespace adds `unknownReason: namespace_unrecorded` (no copy records one, or copies disagree), a reference too long to keep `reference_not_kept` with a null key. Nothing is inferred from names. The host lanes take the selector from this field on the synthetic mapping fixture, whose Button main is a cached copy.

Limitation of this slice: the selector needs a namespace and a key. A key-only or no-namespace question, which #93 still requires to report an unresolved status, is the next identity slice; namespaces are never inferred from names or keys.
