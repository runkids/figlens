# Library usages

Field reference linked from [usages](usages.md): how a stored generation keeps library references and how `usages` with `library` reads them across a workspace.

Library references (#93): a stored generation (`search::index_bytes`) and a stateless full build (`search::loaded` with relations, never a text-only one) keep `uses_library` edges in `Record.library`, off `Record.edges`, so edge readers match builds that skip them (viewer, diff); `store::add` never loads them, only `Graph::library` for one record. The target is the JSON array `[kind, namespace, key]` (kind `component`, `style` or `variable`), so strings cannot collide. The namespace is `sourceLibraryKey` from a cached copy, basis `cached_copy`: a main's own copy (evidence `{"copy": id}`), or for a style or variable assetRef the copies carrying its key (evidence `{"field", "version"}`). References carry no namespace, and a file's own definitions carry no key (keys are server-assigned), so this proves no definition identity. No namespace, no copy or disagreeing copies give `namespace: null`, state `unresolved`; `external` means only that a copy names the namespace. `usages::libraries` charges every node visit and kept key before the scan, and a scan that runs out stops the build.

Library query (`workspace/library.rs`): `usages` with `workspaceId` and `library {kind, namespace, key}` (CLI: a workspace selector plus `--library K [--namespace NS] --key KEY`) reads that exact target in every visible source's published `scope` (`sourceId` narrows to one), sources in added order, then `(rid, seq)`. MCP refuses `file`, `node`, `resource`, `snapshotId`, `relation` and `direction`; a relocated CLI `--file` gets a workspaceId recovery. `definition` is `{state: unresolved, reason: library_source_unproven}` unless `library.definition {sourceId, snapshotId, nodeId}` (CLI `--definition-source/-snapshot/-node`, all three) selects one: in the same read, its source must be visible and ready at exactly that snapshot and the node a record of the published scope (COMPONENT or COMPONENT_SET for component, VARIABLE for variable; a record keeps no style flag, so a style adds `kindEvidence: unverified`). It then reads `{state: selected, basis: caller_ref, ref, keyEvidence: unverified}`: the caller's choice, never resolved from the key, which no file proves. Otherwise it is unresolved with `definition_not_found` (an unknown node, or a source that is unknown or outside the roots: the two read alike, so a hidden source's existence is not told), `source_not_ready`, `definition_snapshot_stale` or `definition_kind_mismatch`; never another node. Without `namespace` the target is `[kind, null, key]`: only copies recording no namespace, with definition reason `namespace_required` (when none is selected) and coverage reason `namespace_required` in place of `namespace_unknown`, never complete; other namespaces are not scanned by key. Each result carries `hidden`, `internal`, `page` and `scopeRoot` from the stored record and the generation's page/root lists, read once a source shows a visible use, their UTF-8 bytes charged to the page before they are copied; no `path`, which would walk ancestors. A page holds 3 MiB of serialized results and coverage, so MCP's text and structuredContent copies fit its 8 MiB cap: `coverage.sources` and up to four copies of each source id in reasons are charged first (coverage alone over the page is `response_budget_exceeded`, asking for `sourceId`), and each use is checked in UTF-8 bytes (`length(CAST(… AS BLOB))`) before it is copied and as serialized after; a later use that no longer fits ends the page with a cursor, one that cannot fit an empty page (beside its source's page and root lists) is `response_budget_exceeded`, whose recovery repeats the question with that `sourceId` (unless one was given) and names the use for `inspect`. `coverage.sources` gives each source's path, state, nextSteps and, when ready, freshness as search reports it (`verifiedAtMs`, `stampCheckedAtMs`, size and modification time equal to the verified snapshot; no hash now). An unreadable file is reported before any not-prepared or pending state; reasons `source_not_ready`, `index_partial` (stopped build, unread fields or an unkept reference), `namespace_unknown` (the key with a null namespace), `hidden_excluded` (not incompleteness) and `authorization_restricted` (sources outside the roots, unnamed). Cursor `l2.<fingerprint>.<source>.<rid>.<seq>.<gens>` binds the reference, the definition ref and its outcome, scope, includeHidden, sourceId, versions, visibility and each source's state, all `cursor_stale` when changed and checked before any generation is looked up; `<gens>` carries each source's generation (`n` when not ready), then the selected definition source's, so a reindexed source is `cursor_stale` while its old generation remains and `cursor_expired` once it is deleted, each checked against that source's own id. The cursor's length is bounded by the source count before it is split.

Naming one: outgoing `usages` (`direction: out`, CLI `--out`) adds `library {kind, namespace, key, basis: cached_copy}` to an `instance_of`, `uses_style` or `binds_variable` result whose record keeps a reference for the same copy (`evidence.copy` = the target) or field and key (`usages::library_of`), stateless and stored alike; a null namespace adds `unknownReason: namespace_unconfirmed` (no copy records one, or copies disagree), a reference too long to keep `reference_not_kept` with a null key. A stateless build (`search::Library::Named`) scans on a copy of its bounds: a scan that does not fit keeps no references and outgoing usages reports `library_reference_unread`, never a stopped build; a stored one (`Library::Stored`) stops so `index_partial` says so. Stateless full builds now pay that scan and keep the references (cached with the index text search reuses); its load and memory cost is not yet measured against the `performance` baseline. Nothing is inferred from names. The host lanes take the selector from this field on the synthetic mapping fixture, whose Button main is a cached copy.

Definition match (`search/fingerprint.rs`): with a `selected` definition each use adds `definitionMatch`, `equal`, `definition_mismatch` or `unknown`, comparing the definition's record with the use's cached copy (`evidence.copy`, read in the use's own generation, never the use's overrides). Only a component use names one copy, so style and variable uses are `unknown`. Fingerprints are captured only while a stored generation is built (`Library::Stored`) and read from `fingerprints (gen, rid, facet, state, digest)` (schema 8), never parsed or built on query. Roots: every stored COMPONENT, COMPONENT_SET, VARIABLE or style node the build indexes, cached copies included; nothing outside the indexed scope.

- Facets `text`, `layout`, `appearance` and `properties` use diff's field lists (`diff::FIELDS`) and its bounded per-field digests. Each folds, in document order over the root and its indexed subtree (expanded instance content included), every record's depth below the root, kind, name and own visibility, then its fields' digests, so a child's text or fill change is a mismatch even when the root is unchanged.
- Per-kind contract: every kind requires all four facets. A component or set folds its subtree; a variable or style is its own record. A set and one variant (different kinds) are `unknown`.
- Canonical: the root's placement in its parent (`transform`, `horizontalConstraint`, `verticalConstraint`, `stackPositioning`, `stackChildPrimaryGrow`, `stackChildAlignSelf`) is left out; children's layout and order are kept; blob indexes digest the bytes they name. No id is stripped: a field whose value holds a GUID (a paint's variable alias, `componentPropDefs`/`Refs`/`Assignments`, `variableSetID`, `variableDataValues` mode ids, `variableModeBySetMap`, `prototypeInteractions`) maps to no confirmed key, so its facet is `unsupported`.
- `unread`: a field over diff's caps, hidden content left unexpanded in the subtree, a subtree the build cut short, or an expansion stop.
- `definition_mismatch` when a facet read and supported on both sides differs; `equal` when all four are and none does; otherwise `unknown`. The definition stays `caller_ref` with `keyEvidence: unverified`: `equal` says the cached copy matches the caller's choice, not that the library published it. Results keep the consumer's own values.
- Cost: each definition-subtree record's facets are charged to the build's bounds (a stop is `index_partial`); the fold is charged per record and field, and 96 bytes per stored row, before it runs. Load and memory cost against the `performance` baseline is not yet measured.
- Coverage: `definition_mismatch` with the page's `count` (a finding; `complete` unaffected); `definition_not_compared` with `count` and a `nextSteps` index refresh of the definition's source and scope when its generation holds no fingerprint for the node (`complete` false, never an implicit build). Without a selected definition replies are unchanged.
