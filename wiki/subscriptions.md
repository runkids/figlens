# Change subscriptions

`watch subscribe|list|unsubscribe|forget` (`src/workspace/changes/subscriptions.rs`; schema 5, numbered after B2's watch schema when that lands) keeps durable subscriptions: one consumer follows one visible source, scope or exact node (its kind in the published index is the anchor: no layer is `target_missing`, two kinds are `identity_uncertain`, a later other kind reads as `identity_uncertain`; never a same-name match). Each holds its own checkpoint, bound to its id and `FILTER_VERSION`, starting at the newest revision its view sees; `changes`/`ack` with `subscriptionId` refuse `consumer`, `sourceId` and `scope`. A node subscription reads revisions whose changed rows name the node or have it as top-level frame, plus baselines, incomplete details and incomplete comparisons (`coverage.complete` not true), since either may hide its change (a deeper node's descendants are not matched yet). The subscribe reply is read inside its write, so it never describes a source moved out of view meanwhile. `owner` marks a temporary subscription removed by `unsubscribe --consumer C --owner O`; one consumer cannot hold the same target under two owners or lifetimes, and a repeat reports `initialPosition: existing`. `forget` ignores sources removed since a view was written. Raw consumer rows now record the visible sources they were written under; `forget` removes only rows whose sources the caller sees all of, and legacy rows only for a caller who sees every source (else counted in `keptUnknownOwnership`). A consumer holds at most 64 subscriptions and raw checkpoints, a workspace 4096, checked in the writing transaction: past that a new one is `workspace_busy` naming list, unsubscribe and forget; nothing is evicted. Visibility is resolved inside each transaction; a subscription on a hidden source reads as unknown. Removing a source deletes its subscriptions.

Hosts: CLI `watch subscribe|list|unsubscribe|forget` and `changes|watch ack --subscription`, MCP `watch` actions of the same names and `subscriptionId`; Pi and OMP use the shared MCP tools; OpenCode's CLI path maps them through `figlens_watch` and `figlens_changes`, asking edit on the workspace for every action but `list`. The served skill's Following changes section routes subscribe after the baseline, unsubscribe to stop following (never `untrack` unless asked) and `owner` only for task-temporary subscriptions. Revision recording and `ack` semantics are in [changes](changes.md).
