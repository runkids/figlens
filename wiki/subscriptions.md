# Change subscriptions

`watch subscribe|evaluate|list|unsubscribe|forget` (`src/workspace/changes/subscriptions.rs`; schema 6, after the watch schema 5) keeps durable subscriptions: one consumer follows one visible source, scope or exact node (its kind in the published index is the anchor: no layer is `target_missing`, two kinds are `identity_uncertain`, a later other kind reads as `identity_uncertain`; never a same-name match). Each holds its own checkpoint, bound to its id and `FILTER_VERSION`, starting at the newest revision its view sees; `changes`/`ack` with `subscriptionId` refuse `consumer`, `sourceId` and `scope`. A node subscription reads revisions whose changed rows name the node or have it as top-level frame, plus baselines, incomplete details and incomplete comparisons (`coverage.complete` not true), since either may hide its change (a deeper node's descendants are not matched yet). The subscribe reply is read inside its write, so it never describes a source moved out of view meanwhile. `owner` marks a temporary subscription removed by `unsubscribe --consumer C --owner O`; one consumer cannot hold the same target under two owners or lifetimes, and a repeat reports `initialPosition: existing`. `forget` ignores sources removed since a view was written. Raw consumer rows now record the visible sources they were written under; `forget` removes only rows whose sources the caller sees all of, and legacy rows only for a caller who sees every source (else counted in `keptUnknownOwnership`). A consumer holds at most 64 subscriptions and raw checkpoints, a workspace 4096, checked in the writing transaction: past that a new one is `workspace_busy` naming list, unsubscribe and forget; nothing is evicted. Visibility is resolved inside each transaction; a subscription on a hidden source reads as unknown. Removing a source deletes its subscriptions.

A `query` subscription (`src/workspace/changes/queries.rs`) saves one workspace search of one source's scope (default `0:0`, hidden and internal layers excluded, `type` sorted): its target is the search's own normalized phrase, terms and types, so spellings search normalizes alike are one subscription. Its events are evaluations in `query_evaluations` (cascade-deleted with the subscription), not revisions. A new subscribe stores the first after its own write (`initialPosition: initial_evaluation`, a failed one reported as `unavailable` with an evaluate step; a repeat evaluates nothing); `watch evaluate` stores the next. `type` without `query` is refused. Each runs `query::search` with `limit` 50 outside any write, reading the publication before and after it (unequal is `pending: newer_publication`), and publishes inside one IMMEDIATE write only when the subscription, its target and that publication still hold; the same generation, membership and ranking is `current`, writing nothing, and a new generation whose snapshot, coverage, ranking and window are unchanged only rebinds the newest evaluation to it (no event, nothing evicted). A stale, unreadable, incompatible or too-large index is `unavailable: search_failed` with the search's recovery; a removed or hidden subscription is unknown; a target search now normalizes differently is `unavailable: query_changed` (resubscribe). The runner's hook `changes::evaluate_published(source, scope, from, cancel)` works in bounded turns: one call runs at most one canonical search that a subscription is due for (no evaluation and no noted failure at the scope's publication; indexed by `subscriptions_query`) and one short write recording it for at most `FANOUT` (32) of them, a savepoint each. The returned in-memory `Continuation` keeps the publication, position and that search's outcome, so later turns record the rest without searching again; at another publication it restarts from the first search, and `None` discovers due work. `cancel` interrupts the search in progress (SQLite through its interrupt handle, and the load, posting and ranking loops through `query::search_with`, which plain `search` skips); a cancelled turn writes and notes nothing, its write checked again after it begins and before commit. Its write waits at most 250 ms for another writer, then fails `workspace_busy` for the runner to retry. A failed search or record is noted on each subscription (`eval_failure`, at most 4 KiB, keyed to the publication), so it is not rerun before the next publication or `watch evaluate`, and `changes` reports it as its stored state with its reason; `watch evaluate` notes its own failures at the publication it read. A hidden source loads nothing. (no CLI or MCP surface; hosts call `watch evaluate` per subscription). `changes` reads them, admitting rows by the actual SQL lengths of the columns it emits before copying or parsing any (a first row past `PAGE_BYTES` fails `response_budget_exceeded` and a damaged first row `source_unreadable` (`InvalidData`), each with an ack-past recovery; a damaged later row ends the page before it), and reports `current`, `current_for_index` (the file's size or mtime differs from the published snapshot, or it is gone: refresh, then evaluate), `pending` with an evaluate step, or `unavailable`, with the view's `tracking`; it never writes. Causes: `source_changed` only for another snapshot, `index_rebuilt` for the same bytes, `coverage_changed`, `ranking_changed`, `corpus_changed` (membership). `enteredTopK` and `leftTopK` compare the two top-50 windows as exact refs in the new and the old snapshot (`snapshotId`, `fromSnapshotId`), `rankChanged` is null when the rankings differ (`rankComparable: false`), nodes are compared by `sourceId`, which relocate keeps (membership only fences the computation; remove deletes the subscription), and `delta.from` names the evaluation compared, since publications between evaluations are coalesced; `total` is set only when nothing ranked past the window and coverage is complete. Each keeps 16; pruning raises `pruned_seq`, which the cursor receipt binds, so a checkpoint or cursor behind it is `event_gap`. One evaluation may take half of `PAGE_BYTES`, so it always fits a page with the reply's own fields (else `unavailable: evaluation_too_large`, nothing written); the workspace's evaluation bytes are capped at 8 MiB and the database's used pages (page count less freelist, so rows deleted by unsubscribe make room) at `DISK_CAP`, both checked before the insert: past that is `workspace_busy`. A relocation always draws a new random membership (`registry.rs` relocate), so a source moved away and back during a search never matches the membership read before it. Calling the hook from the runner (with FF) is not wired yet.

Hosts: CLI `watch subscribe|evaluate|list|unsubscribe|forget` and `changes|watch ack --subscription`, MCP `watch` actions of the same names with `subscriptionId`, `query` and `type`; Pi and OMP use the shared MCP tools; OpenCode's CLI path maps them through `figlens_watch` and `figlens_changes`, asking edit on the workspace for every action but `list`. The served skill's Following changes section routes subscribe after the baseline, unsubscribe to stop following (never `untrack` unless asked) and `owner` only for task-temporary subscriptions. Revision recording and `ack` semantics are in [changes](changes.md).
