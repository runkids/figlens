# Copied selections

Part of the `parsing` topic. Load it when changing `figlens clipboard` or how figlens treats a `.fig` made from a copied selection; decoding rules are in [fig-format](fig-format.md).

## Spike findings (2026-11-03, #206)

`figlens clipboard [copied.html] <out.fig>` (`src/clipboard.rs`) turns a selection copied in Figma, read from the clipboard's HTML, into a `.fig` holding only `canvas.fig`, so every command and MCP tool reads it through `Document::open`. Spike on one real copy (Task Flow community file, frame `2:54`, macOS desktop app; other platforms and the browser are unchecked):

- Wrapping: `<span data-metadata="<!--(figmeta)B64(/figmeta)-->">` holds JSON (`fileKey`, `pasteID`, `dataType`, `selectedNodeData`, `imageHashes` → signed S3 URLs that expire); `<span data-buffer="<!--(figma)B64(/figma)-->">` holds a `fig-kiwi` canvas (version 106) that the existing parser and budgets decode unchanged. The message adds `pasteFileKey`, `pastePageId`, `pasteID`, `isCut` and `publishedAssetGuids`. figlens reads only the buffer; the signed URLs are never copied.
- Ids: the copied layers keep the source file's ids (486 of 487 nodes match; the extra is the internal page). The selection sits on a page; the components its instances use come along on an `internalOnly` "Internal Only Canvas", so instances expand. The copies gain `componentKey`, `publishID` and `sourceLibraryKey`, so `nodes` lists those components `remote: true` with a `key`, where the saved file says local.
- Missing: no image bytes (only hashes), and no `fillGeometry` (215 nodes) or `strokeGeometry` (55), only `vectorData.vectorNetworkBlob`. figlens draws an outline-less vector's fill as its box and its stroke around the box, so `render::diagnostics` names `fillGeometry`/`strokeGeometry` when the field is absent (never on an empty list; zero on three saved community files), and `export` warns for each visible image paint whose bytes are absent and each instance whose component is absent (on any `.fig`, not only copies). Otherwise `nodes 2:54` matched the saved file except vector render bounds.
- The command reports `missingImages`, `missingComponents` (instances whose component, swap first, is not in the copy) and `layersWithoutOutlines` (a count of vector-like layers missing either outline), refuses an existing output (a full design saved over with a partial copy is lost) and bounds the HTML at 4/3 of the canvas ceiling plus 16 MiB before decoding. Decoding `vectorNetworkBlob` into outlines is not done.
- Interfaces (2026-11-03): only the CLI converts. MCP, Pi, OpenCode and OMP read the converted `.fig` with their existing tools (MCP: inside its roots), and their `export` gets the same warnings through `export::export`. A server reading the user's clipboard is out of scope.

## Reading the system clipboard (#218)

Pasting a copy into a text field gives the clipboard's plain-text flavor, only the layers' text (about 0.7 KB beside about 100 KB of HTML in the spike), so users could not tell what to save. With one argument the command reads the HTML flavor by name: macOS `osascript -e 'the clipboard as «class HTML»'` (hex inside `«data HTML…»`, read at twice the HTML budget, then decoded), Windows PowerShell 5.1 `Get-Clipboard -TextFormatType Html` (CF_HTML; the markers are found past its header; PowerShell 7 lacks the parameter), Linux `wl-paste --type text/html`, then `xclip -selection clipboard -target text/html -out`. A reader that runs and fails means the clipboard holds no Figma layers, and the error says to copy layers rather than paste text; it also names a missing reader, since wl-paste fails outside Wayland where xclip would work. When none can run, the error names the tools; AppleScript's hex is decoded in place so the payload is held once. Only macOS was checked against a real copy.

A saved `.fig` is the better source when one exists: a Figma link passed as the node keeps images and vector outlines. The skill tells agents to look for a project `.fig` first and match a link's file-name segment to it; a saved `.fig` does not store the plain file key (its `originFileKey` is a 131-character opaque value), while a copy's `pasteFileKey` is the link's key.
