# Discovery output

What `find` and `inspect` return: bounded summaries for locating and reading a node. Full design data stays in `nodes` and `bundle` (see `fig-format`); ranked effective-content search is the `search` topic.

## Summaries

- Discovery lives in `src/command/discover.rs`: `find` searches stored layer names/text in deterministic breadth-first tree order, returns paths, local pre-rotation sizes and up to 200 results (default 20); instances are not expanded. `inspect` projects existing REST output into bounds/layout/typography and text previews, expands instances, and caps output at 200 nodes, depth 0-10 (default 1), 200 characters per text. A parent with children and no `layoutMode` (except `BOOLEAN_OPERATION` and the document) gets `childSpacing: "derived"`, since its gaps are coordinate differences; flex auto-layout spacing stays in `itemSpacing`/padding, grid gaps appear only in the `gridLayout` handoff diagnostic, and absolute children keep `layoutPositioning`. `childCount` includes omitted children; `truncated` marks omitted descendants/results, `textTruncated` shortened text. Summaries limit output, not decoding/expansion cost. Both tools return structured JSON over MCP; full `nodes` output is unchanged. `inspect --flat` (MCP `flat`) walks the same REST document with the same limits but prints one line per node (`flat_lines`): `absoluteBoundingBox` relative to the inspected root, visible paints (solid as hex with `/alpha`, others by type), per-side stroke weights before `strokeWeight`, radii, auto-layout (or `spacing=derived` under the same rule as `childSpacing`, shared through `derived_spacing`) and opacity; `children=N` marks depth cuts and `… N more` node-limit cuts. Over MCP the text is also `structuredContent.flat`, so `node` is absent; it cannot be combined with images, states or compareVariant.
