# Discovery output

What `find` and `inspect` return, and how `export --match-dir` finds a project's existing icon: bounded summaries for locating and reading a node. Full design data stays in `nodes` and `bundle` (see `fig-format`); ranked effective-content search is the `search` topic.

## Summaries

- Discovery lives in `src/command/discover.rs`: `find` searches stored layer names/text in deterministic breadth-first tree order, returns paths, local pre-rotation sizes and up to 200 results (default 20); instances are not expanded. `inspect` projects existing REST output into bounds/layout/typography and text previews, expands instances, and caps output at 200 nodes, depth 0-10 (default 1), 200 characters per text. A parent with children and no `layoutMode` (except `BOOLEAN_OPERATION` and the document) gets `childSpacing: "derived"`, since its gaps are coordinate differences; flex auto-layout spacing stays in `itemSpacing`/padding, grid gaps appear only in the `gridLayout` handoff diagnostic, and absolute children keep `layoutPositioning`. `childCount` includes omitted children; `truncated` marks omitted descendants/results, `textTruncated` shortened text. Summaries limit output, not decoding/expansion cost. Both tools return structured JSON over MCP; full `nodes` output is unchanged. `inspect --flat` (MCP `flat`) walks the same REST document with the same limits but prints one line per node (`flat_lines`): `absoluteBoundingBox` relative to the inspected root, visible paints (solid as hex with `/alpha`, others by type), per-side stroke weights before `strokeWeight`, radii, visible effects (`shadow`/`inner-shadow=x,y,blur[,spread],color`, `blur`, `bg-blur`), auto-layout plus `align=main/cross` and `size=w/h` when REST emits a non-MIN alignment or non-HUG sizing (#166), without a grid gap, which REST does not emit (or `spacing=derived` under the same rule as `childSpacing`, shared through `derived_spacing`) and opacity; `children=N` marks depth cuts and `… N more` node-limit cuts. Two opt-ins serve implementing a screen without parsing `nodes.json`, on `inspect` and `--flat` alike (default output unchanged, as for `--images`): `--full-text` (MCP `fullText`) lifts the 200-character text preview to 10,000 characters (`textTruncated` beyond; MCP reply budgets still apply); `--colors` (MCP `colors`) adds `solidFills` `[{hex, opacity?, variableId?, variableName?}]` for visible SOLID fills of any node (TEXT color included), where `opacity` is paint alpha times paint opacity only, not node or ancestor opacity, and the variable name comes from the same lookup as `variables`; on `--flat` a fill gets a `$name` suffix. Gradients, images, strokes, effects and vector geometry stay out. Over MCP the text is also `structuredContent.flat`, so `node` is absent; it cannot be combined with images, states or compareVariant.
- Screen lists: `tree --top-frames` (MCP `topFrames`) lists the screens under its root in tree order, each line starting with its id as `frame_ids` reads it: `FRAME`, `COMPONENT`, `COMPONENT_SET` and `INSTANCE` children of a page or of a section on one, at any section depth. Groups are skipped, which drops canvas labels (a group around one wide, short frame) but also a screen wrapped in a group; list that with `tree <group>`. Internal pages (`internalOnly`, such as Figma's hidden canvas of library copies) are skipped unless they are the root. `--json` gives flat `tree` entries without children plus `page` and innermost `section`. `--top-frames` fails on sections nested more than 256 deep, and `tree` listing more than 256 levels (the default) on a file deeper than that ([layer depth](parsing.md#layer-depth)).
- Canvas labels (#79): in `tree --json`, a child of a page or section adds `firstText`, the characters of the first visible, non-blank stored TEXT in its subtree (itself included), breadth-first, hidden subtrees skipped, instances not expanded, at most 200 characters; absent without one. It lets callers filter labels, which `--top-frames` still lists when the label frame is not wrapped in a group. A `role: "label"` guess was not added: across ten sample files, top-level frames and groups holding exactly one visible TEXT were mostly UI fragments (968 `Content` frames in one kit, 69 chip-sized groups in another), not labels. Only those children are searched, so whole-document `tree --json` time on the two largest samples stayed within run-to-run noise (335-344 vs 340-347 ms, 485-509 vs 485-508 ms over three runs).

## Matching project icons

- `export --match-dir DIR` (MCP `matchDir`, SVG output only, single and batch; `export::SvgIndex`) parses each `.svg` under `DIR` once with usvg (no href loads; links not followed, files over 1 MiB and unparseable files skipped; more than 10,000 SVGs, 64 MiB of SVG or 100,000 directory entries refuse the folder; an unreadable entry fails the call with its path; skipped oversized files count toward the 64 MiB). `matches`: every drawn path flattened to page space, moved to the origin, a line back to the subpath start before a close dropped, points within 0.01, so translation, paint, ids, path syntax and `<path>` splits do not matter. `similar` (up to 10, score >= 0.8): the same outlines uniformly scaled score 1; otherwise the drawing's stroke bounds are fitted into 64×64, only pixels of its main color count (a white glyph on a badge is a hole) and the score is the smaller share of each mask within 2 px of the other, so line weight and stroked vs outlined drawing matter little. A shape too thin to cover a 64×64 pixel keeps an empty mask and still matches exactly. Equal outlines also need agreeing paint-blind coverage masks (any alpha counts, so translucent and mixed-opacity paths register; the similarity mask's ink is alpha ≥ a quarter of the most opaque pixel) (overlap ≥ 0.95), since fill vs stroke or even-odd vs nonzero paint the same segments differently, while optimizers rewrite even-odd as nonzero when the winding allows; a clip path or mask on either side turns off the outline comparison, so a clipped export is compared by mask only. The export file itself is never reported.
