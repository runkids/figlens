# Saved copy freshness

Load this to change `freshness`, `pull`, the `.figlens/sources.json` mapping, or the stale hint on a missing node. A saved `.fig` is a snapshot: when a designer adds a frame after the save, an agent gets `node not found` (or an empty `find`) and would report a design gap. This tells it the copy is older than the online file instead (#224). `freshness` downloads nothing; `pull` refreshes copies through the person's own browser sign-in.

Code: `src/freshness.rs` (mapping, saved time, REST call, comparison), `src/command/freshness.rs` (the shared request and `with_hint`), `src/main.rs` (CLI `freshness`, the hint on read commands), `src/mcp.rs` and `src/contract.rs` (the `freshness` tool, `sources` admission, the hint on design tools).

## Sources and comparison

| Side | Source | Why |
|---|---|---|
| Saved | `exported_at` in the `.fig`'s `meta.json`, read through `open_zip` with a 1 MiB entry cap | File times change on every checkout or copy. A file without it (the public fixture, `clipboard` output) is `unknown`/`no_saved_time`, never guessed. |
| Online | `file.last_touched_at` (and `version`) from `GET /v1/files/:key/meta` | Tier 3 and scope `file_metadata:read`, against Tier 1 and `file_content:read` for `GET /v1/files/:key?depth=1`, which also returns the components and styles maps. Checked 2026-11-04 in Figma's file-endpoint and rate-limit docs. |
| Compare | Both parsed to epoch milliseconds (`millis`, RFC 3339 with any fraction or offset) | String order fails across precisions (`49Z` against `49.965Z`). Online later than saved is `stale`; otherwise `current`. |

The request runs `curl` (no HTTP dependency in the binary, like `gcloud` for `gs://`), with `-q` (no `~/.curlrc`), a 5 s connect and 10 s total timeout and a 1 MiB response cap. The token comes only from `FIGMA_TOKEN` and reaches curl as a `header = "X-Figma-Token: ..."` config line on stdin, so it is never on a command line or in output. A token holding `"`, `\` or control characters is refused (`token_invalid`) rather than escaped. The file key comes from a `design`, `file` or `proto` URL (a `/branch/<key>` URL's branch key; a file whose name slug is `branch` keeps its own key), ASCII alphanumeric only.

`unknown` reasons: `no_token`, `deadline` (a listing starts no request it could not finish within 60 s, since it holds the MCP interactive lane), `cancelled` (MCP `notifications/cancelled` or the server stopping), `no_saved_time`, `not_mapped`, `file_missing`, `url_unrecognized`, `outside_roots` (MCP), `curl_unavailable`, `offline` (curl failed or timed out), `token_rejected` (401/403), `file_not_found` (404), `rate_limited` (429), `unexpected_response`, `token_invalid`. None of them fails the command, and every `unknown` design carries all the report's fields, null when unknown.

## Mapping

`.figlens/sources.json` at a project root: a JSON list of `{name, url, file}` with `file` relative to the project root (the folder holding `.figlens/`); a mapping anywhere else, given by `--sources`/`sources`, names files relative to its own folder. `.fig` copies can live anywhere a mapping names, but the stale hint finds a copy's mapping by walking up from the copy's own folder, so a copy outside the project folder gets listings and no hint. It sits in `.figlens/` beside the committed `component-mappings.md`, figlens's project folder (user decision 2026-11-04, over `figma/sources.json`), and is committed too. Limits: 1 MiB, 200 entries; a malformed entry fails the listing with its index. `--sources`/`sources` reads another path by the same rule, made absolute first so a bare `.figlens`-relative `sources.json` still resolves from the project root. Discovery walks up from the CLI's working directory, or from a checked file's folder, to the first `.figlens/sources.json`; under MCP roots a mapping outside them is skipped, and an entry outside them is `outside_roots` (a missing file whose existing ancestor is inside them is `file_missing`). `pull` reads the same mapping. Optional `account` selects a named browser session for pull only; `freshness` and the stale hint still use the single `FIGMA_TOKEN`. If present, `account` must be a string of 1–64 lowercase ASCII letters, digits, `_` or `-`, beginning with a letter or digit; null, empty and path-like aliases are refused before a browser starts. Never put credentials or tokens in this committed mapping.

## Command and tool

- CLI `figlens freshness` lists the nearest mapping; `<file.fig>` checks one file from its nearest mapping (`file_missing` when it does not exist, `not_mapped` when no mapping lists it); `<file.fig> --url URL` needs no mapping; `--sources PATH` lists that mapping. Prints `{mapping, tokenVar, tokenSet, designs: [{name, file, savedAt, onlineModifiedAt, onlineVersion, state, reason}]}`.
- MCP `freshness` takes the same as `sources`, `file` and `url` (no working directory, so one of `sources`/`file` is required). It refuses `gs://`. Annotations: read-only, open world. It runs on the interactive lane and never loads the warm document.
- Pi, OpenCode and OMP discover the tool from the server's `tools/list`; no adapter change ([integrations](integrations.md#package-and-shared-behavior) records the `FIGMA_TOKEN` environment caveat). Their READMEs describe it under "Checking a saved copy"; the MCP parameters are in [mcp-contract](mcp-contract.md). OpenCode's CLI-path fallback tools (used when its MCP server is disabled) have no `freshness`; it covers the search flow only.
- The Herdr panel (`herdr/`) needs no change: it runs CLI `find` and `inspect`, ignores a `find` reply's `freshness` and shows the hinted error text as is. With `FIGMA_TOKEN` in Herdr's environment, each empty panel search on a mapped copy makes one request, since separate CLI processes share no hint cache.

## Stale hint

`with_hint` wraps tree, find, inspect, node, nodes, variables, bundle and export in the CLI, and every design tool's result in MCP. Only a `NodeNotFound` error, or a find with no results, looks further, and only with `FIGMA_TOKEN` set, a mapping found from the file's folder and an entry naming that file does it make one request. The answer (stale or not) is kept per path, modification time and size for 60 s, and concurrent misses on one copy wait for the first, so an agent trying several ids makes one request; a re-saved copy is checked again. `stale` and the `freshness` report share `source_for` to find a file's mapping entry. A stale copy appends the "save a new local copy" sentence to the error (kind and recovery kept), or adds `freshness` (the design report plus `hint`) to the find reply. `nodes --ids`, `export --frames`/`--batch`, `compare` and `gs://` sources do not carry it.

## Pull

`figlens pull` (#225, CLI only: it can open a login window and wait minutes, which suits no MCP call) refreshes mapped copies. Code: `src/command/pull.rs` (selection, lock, validation, replace) and `npm/pull/helper.mjs` (the browser).

- Selection: with neither `--only` nor `--stale`, nothing is downloaded and the `freshness` listing prints with a `hint` (#225: list, do not download everything). `--only NAME` (repeatable; an unknown name fails before the browser), or `--stale`, which runs the freshness check and pulls only `stale` copies and missing files (needs `FIGMA_TOKEN`); others are `skipped` with `current` or the unknown reason. Before the browser, each selected entry must have a URL figlens can key, a name no other selected entry uses (downloads come back by name) and a `file` of plain relative parts (no `..` or absolute path, so a cloned mapping cannot aim a pull outside its project); unselected entries are not checked. `--login` reads no mapping. `--logout` reads none either and starts no helper: under the lock it deletes every legacy and named browser profile and prints `{logout, removed}`; its only permitted companion is `--account NAME`, which deletes just that account and includes `account` in the report.
- Accounts (#241): `--account NAME` overrides each selected entry's `account`; with neither, the legacy default stays at its original paths with all cookies (no migration or forced sign-in). `--login --account work` signs into that alias without a mapping. Mixed selections group by effective account in first-appearance order, then invoke the helper once per group sequentially; one group's profile/export/helper failure preserves its failed targets and does not block later groups. Never retry a denied design under another account. An alias labels a browser profile, not a verified Figma identity: the user chooses the identity in the login window.
- State lives in per-user `pull/` (0700): `lock` (an OS file lock, released on process exit), legacy `profile` (playwright-core) and `agent-browser-profile`, named `accounts/account-<alias>/` containing the same two browser folders, and `downloads` (cleared under the lock at start and end). Profiles are 0700 and shared across projects of this user; browsers stay separate because their Chrome builds may not read each other's cookies. The `account-` prefix avoids reserved directory names on Windows. Profile directories cannot be symlinks; validate `accounts/` before traversing it, including logout.
- Browser accounts never select API tokens. `--stale` still requires the one `FIGMA_TOKEN`; existing copies whose metadata is unknown (including 401/403 under that token) are skipped, while missing files remain eligible. Use `--only NAME` to pull through the mapped browser session when the token cannot check that design; never probe other accounts or add named token credentials to the mapping.
- Helper contract: figlens runs `FIGLENS_PULL_HELPER` (`node` for `.mjs`/`.js`; the npm launcher sets it to its `pull/helper.mjs`), writes one JSON line `{profiles: {playwright, agent-browser}, browser, downloads, login, designs: [{name, url}]}` (`browser` is `--browser`, or null) with key-only `https://www.figma.com/design/<key>/` URLs, and reads one stdout line per design, `{name, path}` or `{name, stage, error}` (`open`, `editor`, `menu`, `export`, `download`). stdin stays open until stdout ends, and the helper exits when it closes, so a killed figlens leaves no Chrome on the profile; figlens kills the helper on its own errors. stderr is relayed as progress, and its last line is the reason for designs the helper never reached. Retain completed install results on stream/wait errors; only unfinished designs fail.
- Install: the path must be inside `downloads`; the file must open and decode (`Document::open` and `take_message`), carry `exported_at`, and not be older than the current copy's; then `output::write` replaces it (an exclusive sibling renamed over it, keeping the target's permissions and symlink); install failures have stage `install`. Any failed check leaves the target as it was. No backup is kept.
- Report `{mapping, designs: [{name, file, state: pulled|skipped|failed, savedAt, reason}]}` on stdout in selection order; named selected designs add `account` (including skips/failures), while default designs keep the old shape. Named login/logout also add `account`; the command fails when any design failed, after printing it.
- Browser: `--browser playwright|agent-browser`, else `playwright-core` when the helper finds it, else `agent-browser` on PATH; with neither, the error names both installs. Both run the same flow below behind one page interface in `helper.mjs`.
- The helper finds `playwright-core` beside itself (a global install) or in the working directory's project, launches the installed Chrome (`channel: 'chrome'`) with the profile, sends the regular Chrome user agent in both modes, and on an expired session relaunches headed at `/login` and waits up to 10 minutes for `/files/`. Per design: open the key-only URL (a percent-encoded name slug made CloudFront answer 403), wait for `Main menu`, then File > Save local copy (English UI only; refused when disabled), and take Playwright's download event within 10 minutes. It stops at the first failure within its account group.
- `agent-browser` (checked on 0.38.1) runs the same steps as CLI calls in the fixed session `figlens-pull` (the lock allows one pull), closed on exit and on SIGINT, SIGTERM and SIGHUP; one left by a SIGKILL is closed by the next launch, with `--profile`, `--download-path downloads/agent-browser`, `--headed`, `--user-agent` (Chrome, not HeadlessChrome) and `--idle-timeout 10m` as launch flags; launch flags apply only when the session's browser starts, so each launch closes the session first. Waits poll `eval` (a failed poll, as during a navigation, keeps waiting), since `wait` takes no timeout for selectors, with `AGENT_BROWSER_DEFAULT_TIMEOUT` raised to the 120 s editor wait for heavy navigations. The download is not taken from `download` or `wait --download`: one CLI call gave up after about 150 s waiting on its daemon, under a Figma export's minutes. Instead the click lands in the session's download folder, done when its one file has no `.crdownload` suffix (Chrome's partial name) and the same size on two polls, then it is renamed to `downloads/<index>-<name>`. Export progress checks run one at a time, each after the last returns. Known gaps: a download Chrome abandons shows as `export` after the 10 minute wait rather than `download`; the user's agent-browser config and `AGENT_BROWSER_*` environment still apply (a `cdp` or `allowedDomains` setting breaks the profile launch); Windows npm `.cmd` shims are not found, since the helper spawns `agent-browser` without a shell.
- Ported from a project script that ran this flow with `agent-browser` (2026-11-04 handoff). Not exercised against Figma in CI: `tests/freshness.rs` drives the CLI with a shell helper stand-in, and `npm/pull-helper.test.mjs` checks the messages with neither browser and with `agent-browser` missing, and runs the agent-browser flow against a stand-in CLI, including the session closing on SIGINT. Signing in from the automated profile was reported to sign the person out of Figma elsewhere (unconfirmed); `--help`, the docs table and the skill say so.
- Pi, OpenCode, OMP and Herdr: no tool or adapter; named browser accounts remain CLI-only, and MCP freshness accepts account-bearing mappings without changing its parameters or token lookup. The skill's `Refreshing a saved copy` section (served by `workflow` build, audit and yolo; the MCP instructions point at pull) tells the agent when to pull, to ask first, to leave the sign-in to the person, and what each failure `stage` calls for.

## Tests

`src/freshness.rs` unit tests cover time parsing, URL keys, mapping resolution, `exported_at`, stale/current/rejected with a `curl` stand-in script, and the token staying off curl's arguments. `tests/freshness.rs` runs the CLI and MCP server with a `curl` stand-in on PATH: listing, a bare relative `--sources`, a missing file, no-token calls nothing, the hint on a stale copy and not on a current one, CLI and MCP find, MCP inspect of a missing node, every field on an unmapped file, one request for repeated misses, pull's replace, refusals (older, not a `.fig`, outside its folder), `--stale` skipping a current copy, the key-only URL, an unknown name, the default listing, a file outside the project, a name mapped twice, an unselected bad URL, `--login` with no mapping, the chosen browser and its profile in the request, an unknown `--browser`, `--logout` deleting both profiles and refusing other flags and a mapping, and the helper's last stderr line as the reason, root refusal and a bad flag's usage. Account tests cover legacy cookies and both browser paths, named login without a mapping, grouping and CLI precedence, targeted/all logout, invalid aliases, symlink refusal, single-token stale skips, MCP reading account-bearing mappings, continuing after profile/helper failures without overwriting failed copies, retaining completed results on stream errors, and account-preserving login recovery. `src/mcp/tests.rs` checks the tool's annotations and parameters. No test reaches Figma; the real endpoint was not exercised in CI.
